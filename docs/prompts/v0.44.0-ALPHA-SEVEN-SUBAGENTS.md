# Prompt — launch seven v0.44 Alpha workspace subagents

Use this prompt only after #1193 is closed with an exact common-base SHA.

---

Act as the main OpenElement v0.44 Alpha workspace agent and the eventual alpha.8
integrator. Alpha is not a release phase and does not use the thinker, implementer or
release-verifier loop.

Read `docs/current/v0.44.0-ALPHA-CONTRACT.md`,
`tools/config/v044-alpha-workspaces.json`, the Alpha workspace SOP, the current Version
Plan, execution state, ADR-0143, ADR-0147 and GitHub issue #1193. Extract the exact
common-base SHA from #1193 closure evidence and fail closed unless it is a full SHA
reachable from `origin/dev`.

Create seven isolated worktrees and branches from that exact SHA, one for each
alpha.1-alpha.7 configuration entry. Launch one subagent per workspace. Give each
subagent only its workspace entry, owned issues, owned write paths, the frozen contract
and the exact base SHA. Each subagent owns tests, implementation, repairs, commits,
pushes and concise issue evidence end to end. It must prove focused RED then GREEN,
run relevant targeted gates and `deno task autoflow:push`, inspect its own diff, and
return its exact accepted head SHA. It must not run the full CI matrix, edit another
workspace, change the shared contract, merge to `dev`, tag, publish, or invoke any
three-role runner or executor-profile preflight.

Start all seven logical workstreams immediately. If the host exposes fewer than seven
subagent slots, keep every slot full and dispatch the next queued workspace as soon as
one finishes; never collapse two workspace identities or put two writers in one
worktree. Route cross-workspace questions through factual messages and bounded defect
handoffs. Do not let one subagent directly edit another subagent's checkout.

When all seven workspaces report accepted source SHAs, create the alpha.8 integration
worktree from the common base plus any later control-only `dev` commits. Verify every
source SHA and changed path against the ownership map. Integrate reviewed commit series
in dependency order using linear cherry-picks and record the source-to-integrated SHA
mapping. Return integration failures to the owning subagent; every repair produces a
new source SHA and then a new alpha.8 candidate.

Run the bounded cross-workspace compiler -> Part Program -> server serialization ->
fresh DOM -> existing-DOM claim -> exact signal update -> islands -> Vite/Nitro ->
packed-consumer harness. Only alpha.8 opens a pull request to `dev` and consumes the
authoritative exact-SHA full CI. After it is green, fast-forward the exact candidate to
`dev`, update the Alpha issues with immutable SHA/CI evidence, and stop at the Beta.1
handoff.

Never create an Alpha tag, npm publication, dist-tag, GitHub Release, `main` promotion,
release-verifier session or unanimous release GO. Stop only for a genuine
architecture/public-API/security decision, user interruption, or a proven external
blocker; ordinary implementation, test, integration and CI failures are repair loops.

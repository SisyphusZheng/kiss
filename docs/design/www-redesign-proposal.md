# openElement Website Redesign Proposal

> Target release: v0.41.0 (npm-first distribution)\
> Scope: homepage, docs, roadmap, architecture pages, and shared design system.

## 1. Current Problems

1. **No cohesive brand.** The homepage uses a dark gradient + daisyUI tokens + random emoji icons. It looks like a generic starter template, not a framework identity.
2. **Visual hierarchy is weak.** Giant headline is all caps and breaks awkwardly. The terminal demo is small and hard to read. Feature cards use "EL", "UI", "FW", "PR" labels that look like debug output.
3. **Color inconsistency.** Some pages use `gray-*` (roadmap), others use `bg-obsidian` + `indigo` (homepage), others use daisyUI defaults. There is no single source of truth.
4. **Typography is noisy.** Too many sizes, weights, and uppercase labels. The docs use hairline borders and gradients that fight for attention.
5. **No whitespace system.** Pages feel either too dense (docs) or too empty (404).
6. **Mobile is an afterthought.** The homepage hero grid collapses but the terminal/feature cards do not breathe.
7. **No social proof.** A framework site needs trust signals: GitHub stars, release version, used-by/logos, testimonials.
8. **Docs feel like a README dump.** No clear "get started in 60 seconds" path. Code blocks have no copy button or filename tabs.

## 2. Design Direction

**Vibe:** "Industrial minimalism for Web Components."\
**Keywords:** precise, structural, open-source, trustworthy, slightly futuristic but not flashy.

We want the site to feel like the framework itself:

- **Shadow/DSD first** → layered surfaces, subtle depth, no flat gray blobs.
- **Static-first** → fast, no motion bloat.
- **Four-product identity** → Elements, UI, Framework, Protocols are the four pillars of every page.

## 3. Brand Identity

### Logo concept

A minimal abstract mark made of four small squares arranged in a 2x2 grid, forming one larger square. Each quadrant maps to the four products:

```
┌─────┬─────┐
│  E  │  U  │   Elements + UI
├─────┼─────┤
│  F  │  P  │   Framework + Protocols
└─────┴─────┘
```

- The mark is drawn with 2px strokes and 2px gap.
- It doubles as a favicon and a loading indicator.
- The four quadrants can be tinted with the product accent colors below.

### Color system

Replace the current `indigo/teal/gray` lottery with a controlled palette.

```text
Background
  bg-base:      #0B0C0F   (near-black, not pure black)
  bg-surface:   #13151A   (cards, panels)
  bg-elevated:  #1A1D24   (hover, dropdowns)
  bg-code:      #0D0E12   (code blocks)

Foreground
  text-primary:   #F2F3F5
  text-secondary: #9CA3AF
  text-muted:     #6B7280

Brand
  brand:        #6366F1   (indigo-500, keep but refine)
  brand-hover:  #818CF8   (indigo-400)
  brand-dim:    #312E81   (indigo-900, for subtle backgrounds)

Product accents (use sparingly)
  elements:   #22D3EE   (cyan)
  ui:         #A78BFA   (violet)
  framework:  #34D399   (emerald)
  protocols:  #FBBF24   (amber)

Status
  success: #34D399
  warning: #FBBF24
  error:   #F87171
  info:    #60A5FA

Borders
  border:       rgba(255,255,255,0.08)
  border-strong:rgba(255,255,255,0.14)
```

Light mode (auto-generated by inverting surface/background):

```text
bg-base:      #FFFFFF
bg-surface:   #F8F9FB
bg-elevated:  #F1F3F6
text-primary:   #111827
text-secondary: #4B5563
text-muted:     #9CA3AF
border:       rgba(0,0,0,0.08)
border-strong:rgba(0,0,0,0.14)
```

### Typography

Use a single sans-serif family with a clear scale.

```text
Font: Inter (or system-ui fallback)
Mono: JetBrains Mono (or ui-monospace fallback)

Scale
  display:  4rem   (64px)  line 1.0
  title-1:  3rem   (48px)  line 1.1
  title-2:  2rem   (32px)  line 1.2
  title-3:  1.5rem (24px)  line 1.3
  body:     1rem   (16px)  line 1.65
  small:    0.875rem(14px) line 1.5
  caption:  0.75rem (12px) line 1.4

Weights
  regular: 400
  medium:  500
  semibold:600
  bold:    700
```

Rules:

- No uppercase for body text. Uppercase is allowed only for `caption` labels.
- Headlines are sentence case.
- Code is always JetBrains Mono at `body` or `small` size.

## 6. Motion & Interaction

Keep it minimal:

- Hover transitions: `200ms ease`.
- Card lift: `translateY(-2px)` on hover.
- Page load: no full-screen animations.
- Code block copy: brief "Copied" state.
- Theme toggle: instant, no fancy rotation.

## 7. Responsive Strategy

Breakpoints:

```text
mobile:  < 640px
tablet:  640px - 1024px
desktop: > 1024px
```

Rules:

- Nav collapses to hamburger at tablet.
- Docs sidebar becomes a slide-out drawer on mobile.
- Homepage hero stacks vertically on tablet.
- Feature grids go 1 col mobile, 2 col tablet, 3-4 col desktop.

## 8. Accessibility

- Color contrast ≥ 4.5:1 for body text.
- Focus rings: 2px `brand` outline, offset 2px.
- No auto-playing motion.
- All interactive elements keyboard reachable.
- ARIA labels on icon-only buttons.

## 9. Implementation Phases

Phase 1 — Tokens & global shell

- Define the new color/typography tokens in `@openelement/ui` or a `www/theme.css`.
- Rewrite nav, footer, buttons, cards once.
- Add favicon and logo mark.

Phase 2 — Homepage

- New hero, four-product section, code block, feature grid.
- Add GitHub star count and release badge.

Phase 3 — Docs

- New docs landing.
- New docs article layout (sidebar + TOC + code blocks).
- Add copy buttons to code blocks.

Phase 4 — Roadmap & architecture

- Timeline roadmap.
- Comparison cards and diagrams.

Phase 5 — Polish

- Light mode toggle.
- E2E visual regression baseline.
- Performance budget (Lighthouse ≥ 90).

## 10. First File to Change

Start with `www/app/components/page-styles.ts` and the global tokens. Then rebuild `www/app/routes/index/index.tsx` as the proof-of-concept page. Once the homepage looks right, apply the same tokens to nav/footer/docs.

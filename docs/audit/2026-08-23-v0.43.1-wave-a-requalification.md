## Method

Closed issue state and the old PR CI result were treated only as routing input.
For every row below the original failure boundary was compared with the current
implementation, its issue-specific regression was located, and that regression
was executed again as part of the current candidate test matrix. The commands
are reproducible from the repository root unless a row says otherwise.

Common candidate gates referenced below:

- `deno task test` — complete Deno repository suite.
- `deno task examples:check` — every example, including the Supabase starter.
- `deno task typecheck && deno task lint` — package graph types and tracked
  source lint.
- `deno task arch:check && deno task graph:check && deno task
  package-surface:check && deno task interface:snapshot && deno task
  type-safety:check` — architecture and public-contract gates.
- `deno task docs:truth && deno task workflow:check` — current/release truth.
- `deno task test:e2e:browsers` — Chromium, Firefox and WebKit behavior.
- `deno task fullstack:migrations-check && deno task
  fullstack:notes-qualification` — immutable database inputs plus actual Node
  standalone and Wrangler/workerd request-time artifacts.

Provider-backed evidence is identified separately. A checked-in report is not
silently reclassified as a fresh provider run.

## #1125 — explicit Supabase Data API privileges

Implemented by
`20260823110000_explicit_data_api_privileges.sql` as a forward-only,
manifest-hashed migration.

- Revokes table and sequence defaults for `anon`, `authenticated`, and
  `service_role` before granting the reviewed call graph.
- `anon` receives no public business-table operation.
- `authenticated` receives only Notes CRUD, the read surfaces used by the
  starter, Workspace Records CRUD, and the one identity sequence needed by
  direct inserts. RLS remains enabled and authoritative for row ownership.
- `service_role` no longer receives blanket DML. Direct access is limited to
  Notes seed/query, attachment reservation query/cleanup and scan dead-letter
  inspection. Lifecycle work uses explicit SECURITY DEFINER RPCs.
- Every public function starts from an empty EXECUTE baseline; authenticated
  and service roles receive explicit whitelists. Trigger functions are not Data
  API-callable.
- Two-sided `information_schema.table_privileges` comparison and
  `pg_catalog.has_sequence_privilege` / `has_function_privilege` assertions
  abort migration application on privilege drift.

## #1127 — atomic initial replay request and actor audit

`20260823110100_replay_request_audit_atomicity.sql` replaces both admin request
RPCs. Each derives the actor from `auth.uid()`, rechecks the server-owned admin
claim, performs the state transition and inserts `admin_audit` in one PL/pgSQL
transaction. The route's second PostgREST insert was removed.

Admin regressions prove the route calls only the atomic RPC and surfaces an RPC
failure without a follow-up write. PostgreSQL statement failure rolls back the
containing function transaction by construction. A live injected-audit-failure
probe still requires the schema qualification environment and is not claimed
as locally executed.

## #1130 — truthful authenticated JWT boundary

Generated request-time pages carry loader data only through internal
`__openElementData`; loader payloads are no longer duplicated as public page
props. DSD host serialization excludes `data-*` attributes from
`data-ssr-props`, so the short-lived token appears once, only on the intended
Realtime host attribute.

The Realtime island calls `setAuth` and removes `data-access-token` immediately
after a successful handoff. If the attribute is observed before the client
exists, it is retained for `#connect` instead of being lost. Unit and render
regressions prove both behaviors, and the Node/workerd qualification counted
exactly one token occurrence per authenticated response. The existing
provider-browser smoke remains the real Realtime/RLS subscription gate.

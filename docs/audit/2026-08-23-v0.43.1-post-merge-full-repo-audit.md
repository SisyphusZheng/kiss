## Summary

The post-merge audit found **P0 0 / P1 1 / P2 4 / P3 1**. CI was green, but
did not exercise Supabase's new default table privileges, authenticated
request-time JWT HTML, partial commits after database/provider failures, or
unbounded loader data. This report is the input to Wave B (#1125–#1130), not
the final Wave C release verdict.

The three highest risks were fresh-project Data API `42501` failures, nested
function components losing loader/action data during SSR, and partially
committed replay or attachment-delete operations.

## Findings and required closure

| Priority | Finding                                                               | Consequence                                                                   | Closure issue |
| -------- | --------------------------------------------------------------------- | ----------------------------------------------------------------------------- | ------------- |
| P1       | Fresh-project Data API tables lack explicit grants                    | Notes, orders, admin and attachment paths may fail before RLS is evaluated    | #1125         |
| P2       | Nested SSR function components lose data context                      | `useLoaderData`/`useActionData` return `undefined` below the page component   | #1126         |
| P2       | Replay request state and actor audit are separate transactions        | UI can report failure after durable replay request; actor audit can be absent | #1127         |
| P2       | Storage delete precedes quota finalization without recovery state     | object can disappear while quota remains permanently consumed                 | #1128         |
| P2       | Notes loader and schema are unbounded                                 | 1,000 legal 10k-character rows produced 30,409,467 bytes of HTML              | #1129         |
| P3       | JWT gate scans static output while runtime serializes an access token | the documented browser-boundary guarantee is not what the gate proves         | #1130         |

### F1 — explicit Data API privileges

RLS and table privileges are separate controls. A forward migration must grant
only the operations used by Notes, Checkout, Admin and Upload, including any
required sequence/function privileges. Qualification must start from revoked
defaults and execute an `anon`/`authenticated`/`service_role` API matrix.

### F2 — complete-lifecycle SSR context

The page exits its data context before the renderer evaluates nested function
components. The fix must carry request context through complete VNode
evaluation and prove concurrent renders cannot leak values between requests.

### F3 — atomic replay request audit

The request RPC commits `replay_requested`; the route inserts the actor audit
in a second transaction. The RPC must derive the actor from `auth.uid()` and
write both records atomically. Failure injection must prove rollback.

### F4 — recoverable object deletion

Storage and Postgres cannot share a transaction. A tombstone/deletion intent
plus an idempotent reconciler must converge after provider failure, database
failure, process interruption and duplicate delete.

### F5 — bounded Notes data path

Closure requires database constraints, stable keyset pagination and an
explicit Node and Workers response-byte budget using a 10,001-row fixture.
Browser `maxlength` and route validation alone are not database controls.

### F6 — truthful JWT boundary

The existing gate scans unauthenticated static output while the authenticated
Notes route intentionally passes a user token to the Realtime island. Closure
must either redesign that contract or dynamically prove a narrow documented
allowance, `no-store`, and post-initialization DOM cleanup.

## Requirement traceability

## External verification not performed

The audit did not mutate real Supabase, Stripe or Cloudflare environments. It
did not create real Checkout Sessions, send real webhooks/Queues messages,
deploy a Worker, run a real scanner, configure SMTP/OAuth or exercise production
traffic. Local emulators, deterministic providers and dry-runs must not be
reported as those external proofs.

## Release recommendation

Do not merge `dev` to `main` and do not release `v0.43.1` until Waves A and B
are complete and Wave C (#1131) independently returns `GO`. The umbrella gate
is #1133. Publication additionally requires explicit maintainer authorization.

## Why the verdict is not `GO`

The local candidate is internally coherent and all executable local release
gates either passed or used their documented environmental fallback. It is not
yet a release candidate because the four new forward migrations have not been
applied to a fresh/upgrade Supabase qualification database in this audit, no
exact candidate CI run exists, and the real-provider matrix was not run.

This is an evidence sequencing block, not a newly discovered local P1/P2 code
defect. Changing the verdict to `GO` requires evidence; it does not require a
new framework feature train.

## Architecture and public-surface review

- The five-package graph remains acyclic and version-aligned at `0.43.0`.
- No public package entry exposes an `internal/` module path.
- The nested SSR fix is internal protocol plumbing; it adds no exported public
  symbol. Loader data moved from a public host field to an internal field in
  generated SSR code while SPA/manual page hosts retain the documented `data`
  fallback.
- Notes pagination and deletion reconciliation are reference-application
  capabilities, not framework ORM/outbox/session APIs.
- The DSD `data-*` serialization correction removes redundant hydration JSON;
  data attributes remain standard host attributes after upgrade.
- ADR-0140 freezes feature-train work after v0.43.1 while preserving compatible
  0.43.x fixes and allowing a future minor only through a maintainer-approved
  ADR backed by a cross-application need.

Result: **pass** (`arch:check`, `graph:check`, `package-surface:check`,
`interface:snapshot`, `type-safety:check`, `freeze:semantics:check`).

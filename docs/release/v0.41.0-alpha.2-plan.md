# v0.41.0-alpha.2 Version Plan - Signal-DOM Deepening

## Objective

Complete the architecture-review follow-up deferred from v0.41.0-alpha.1. The
focus is narrowing the signal-to-DOM binding seam: extract a `HydrationScope`
value object, split the renderer from the activation layer, and replace the broad
`BindingDescriptor` union with a registry of small binding factories. These
changes are intentionally kept internal; no public JSX syntax or custom-element
API changes.

v0.41.0-alpha.2 is also the release where at least one real static-only consumer
must migrate to `@openelement/core/static` to validate the subpath split shipped
in alpha1; otherwise the split is reconsidered.

## Origin

This plan contains the three architecture-review candidates that were deferred
from v0.41.0-alpha.1 (see `docs/release/v0.41.0-alpha.1-plan.md` -
Architecture Review Follow-Up). They were moved here to keep alpha1 focused on
npm distribution, unified signal-DOM activation, and low-risk cleanup.

## Governance

- No public API breakage unless explicitly listed in **Accepted breaking changes**.
- All changes must pass the same CI gate set as alpha1:
  `fmt:check`, `lint`, `typecheck`, `test`, `graph:check`, `arch:check`,
  `docs:check-*`, `repo:hygiene`, `workflow:check`, `build`, `consumer:packaged`,
  `test:e2e`, `autoflow:ci`.
- E2E regression is a release blocker because these changes touch the core
  signal-DOM paths.

## Workstreams

### v0.41.0-alpha.2 - Architecture Review Candidates (moved from alpha1)

These three candidates were originally identified in the v0.41.0 architecture
review and deferred from alpha1 to keep the alpha boundary focused on npm
distribution, unified signal-DOM activation, and low-risk cleanup.

#### Candidate 3 — HydrationScope (highest priority)

Extract OpenElement hydration state (`#effectDisposers`, `#eventCleanups`,
`#vnodeCache`) into a `HydrationScope` value object that owns lifecycle,
VNode cache, and event cleanup. OpenElement holds one scope instead of three
private collections. Scope exposes `hydrate(shadowRoot, registry)` and
`dispose()`.

- [ ] Create `packages/element/src/hydration-scope.ts` with:
  - `#effectDisposers: (() => void)[]`
  - `#eventCleanups: (() => void)[]`
  - `#vnodeCache: WeakMap<unknown, VNode>`
  - `hydrate(shadowRoot: ShadowRoot, registry: SignalRegistry): void`
  - `dispose(): void`
  - accessors needed by `OpenElement` and `open-element-render.ts`
- [ ] Refactor `packages/element/src/open-element.ts` to hold one `#hydrationScope`
      instead of three private collections.
- [ ] Refactor `packages/element/src/open-element-hydration.ts` to operate on a
      `HydrationScope` passed as argument rather than mutating external arrays.
- [ ] Refactor `packages/element/src/open-element-render.ts` to use the scope for
      VNode cache and lifecycle disposal.
- [ ] Add unit tests for `HydrationScope` with a fake shadow root and signal
      registry; assert lifecycle registration, abort disposal, and nested render
      disposal.

**Files:** `packages/element/src/hydration-scope.ts`,
`packages/element/src/open-element.ts`,
`packages/element/src/open-element-hydration.ts`,
`packages/element/src/open-element-render.ts`

#### Candidate 1 — Renderer / Activation Split

Make `jsx-render-dom.ts` a pure translator and move all signal effect lifecycle
into `binding-activation.ts`.

- [ ] Refactor `packages/core/src/jsx-render-dom.ts`:
  - `renderToDom()` and helpers create DOM nodes and emit `BindingDescriptor`s.
  - No direct `effect()` calls; no `applyBindingDescriptor()` calls.
  - Special tags (`SHOW_TAG`, `FOR_TAG`, `HTML_TAG`, `Fragment`) still produce
    DOM trees but delegate effect wiring to descriptors.
- [ ] Add a small commit pass (e.g. `commitBindings(root, descriptors, lifecycle)`)
      that applies all descriptors to the activation layer in document order.
- [ ] Move `SHOW`/`FOR` lifecycle wiring into `packages/core/src/binding-activation.ts`
      as first-class binding kinds (`conditional`, `list`).
- [ ] Update `packages/core/__tests__/jsx-render-dom.test.ts` to assert descriptor
      emission against a fake element tree where possible.
- [ ] Update `packages/core/__tests__/binding-activation.test.ts` to cover
      `conditional` and `list` bindings.

**Files:** `packages/core/src/jsx-render-dom.ts`,
`packages/core/src/binding-activation.ts`,
`packages/core/__tests__/jsx-render-dom.test.ts`,
`packages/core/__tests__/binding-activation.test.ts`

#### Candidate 2 — BindingDescriptor Registry

Replace the broad union with factory constructors and an internal registry.

- [ ] Define small factory constructors in `packages/core/src/binding-descriptor.ts`:
  - `bindText(node, signal)`
  - `bindAttr(element, names, signal)`
  - `bindClass(element, signal)`
  - `bindEvent(element, event, listener, options)`
  - `bindRender(element, renderFn, lifecycle?)`
  - `bindConditional(anchor, condition, renderFn)`
  - `bindList(anchor, items, renderFn, keyFn?)`
- [ ] Replace the central switch in `applyBindingDescriptor()` with an internal
      registry: `registry.set(kind, applyFn)`.
- [ ] Keep the public `BindingDescriptor` type opaque enough that callers only
      need the constructors and `apply(binding, lifecycle)`.
- [ ] Update CSR and hydration callers to use constructors instead of assembling
      descriptor objects manually.
- [ ] Add tests that register a fake binding kind and assert `apply()` dispatches
      to it.

**Files:** `packages/core/src/binding-descriptor.ts`,
`packages/core/src/binding-activation.ts`

**Recommended sequence:** Candidate 3 → Candidate 1 → Candidate 2.
HydrationScope consolidates the lifecycle/disposal state that Candidate 1 needs
to hand off cleanly; once both are done, the descriptor registry is a natural
shallowing of the activation switch.

## Dependency graph

```text
Candidate 3 (HydrationScope)
        |
        v
Candidate 1 (renderer/activation split)
        |
        v
Candidate 2 (descriptor registry)
```

Candidate 3 should land first because it consolidates the lifecycle/disposal
state that Candidate 1 needs to hand off cleanly. Candidate 2 can be done in
parallel with Candidate 1 once the activation layer is the single owner of
signal-to-DOM effects, but it is safest after Candidate 1 stabilizes.

## Deferred code-quality findings from v0.41.0-alpha.1 PR review

The following OpenCode automated review findings were reviewed during the alpha.1
PR (#50). Most have been addressed in alpha.1; the remaining items are deferred
to alpha.2 and listed below.

### Already fixed in alpha.1

- **textContent routed through `setAttribute`** — fixed by introducing
  `static-prop` descriptor + `applyStaticProp` direct DOM property assignment.
- **`.ts` import extension** — `packages/adapter-vite/src/plugin.ts:32` changed
  to `./generated-data-resolver.js`.
- **Dead exported functions** — `createRouteManifest` and
  `writeRouteManifestModule` removed from `@openelement/content` barrel.
- **Missing `generated-data-resolver` export** — added to
  `@openelement/adapter-vite/deno.json`.
- **Protocol-relative URL bypass in `isSafeLayoutUrl`** — added
  `trimmed.startsWith('//')` rejection.
- **Unguarded `Deno` globals** — `build-ssg.ts` and `ssg-package-resolver.ts`
  now use `typeof Deno !== 'undefined'` with Node `fs` fallbacks.
- **`cleanSsrArtifacts()` not error-wrapped** — wrapped in try/catch in
  `packages/adapter-vite/src/build.ts`.
- **PACKAGE_SURFACE.md heading mismatch** — corrected to "10-package truth
  table".
- **Redundant `export type { NavData }`** — removed from
  `packages/content/src/nav/writer.ts`.

### Still deferred to alpha.2

### Medium

- **Import extension inconsistency within same file** —
  `packages/core/src/binding-activation.ts` and other core files mix `.js` and
  `.ts` imports. Standardize to `.js` across the package.
- **nodeType === 0 couples production to test harness** —
  `packages/core/src/binding-activation.ts:255` checks `nodeType === 0`, which
  only matches `TestNode` mocks. Real `DocumentFragment` nodes are always `11`.
  Either guard behind a test-only flag or remove.
- **Test global mutation without restoration** — some
  `packages/core/__tests__/` files mutate `globalThis.document` and save it as
  `_savedDocument` but never restore it. Risk for parallel test runs.
- **New content modules lack direct unit tests** — `sitemap/plugin.ts`,
  `write-json.ts`, `fs-adapter.ts` added in alpha.1 need coverage.

### Low

- **OptionalPackageStubs type removed from public exports** — inlined as internal
  in `plugin.ts:69`; document if any external consumer existed.
- **`process.exit` import pattern in `build-ssg.ts`** — `process` is imported but
  `process.exit` is no longer used; switch to importing only `cwd` from
  `node:process`.

These items will be triaged and addressed as part of the alpha.2 workstreams
above or rolled into follow-up cleanup issues.

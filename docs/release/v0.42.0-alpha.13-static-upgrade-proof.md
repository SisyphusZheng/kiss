# TP-6 static upgrade proof — evidence record

> Status: evidence for the TP-6 stable decision (ADR-0122 §7: "the migration
> note and the byte-level upgrade proof are TP-6 deliverables that must land
> before acceptance"). Recorded 2026-08-03 on the alpha.13 train, package
> line `0.42.0-alpha.12`. Companion migration note:
> [`v0.42.0-migration.md`](./v0.42.0-migration.md).

This record has two halves: the in-repo freeze tool run against fixed
baselines (the TP-2/alpha.1 ritual), and a consumer-level upgrade proof that
builds the same pure-static project against `0.41.2` and `0.42.0-alpha.12`
from npm. The two halves answer different questions and are reported
separately — no result is rounded up.

## 1. In-repo tool: `check:static-output-freeze`

Command (run at repo root, `www` is the only supported `--site`):

```sh
deno task check:static-output-freeze -- --baseline <ref>
```

Environment: Deno 2.9.1 (aarch64-apple-darwin), 2026-08-03, main at the
alpha.13 documentation train.

**Normalization applied by the tool (honest record):** exactly one — the
`builtAt` ISO timestamp is stripped from every `island-manifests/*.json`
before comparison (build metadata, not site content;
`tools/check-static-output-freeze.ts` header). Everything else, including
content-hashed chunk filenames, is compared byte-for-byte. The same
normalization is applied in the consumer proof below.

### 1a. Determinism self-check — PASS

Both tool runs built the current tree twice: **355 files byte-identical
across runs**. The continuous CI gate form
(`check:static-output-freeze --self-check`, #600) holds on the alpha.13
documentation train.

### 1b. Baseline `v0.41.2` — FAIL (content drift, as predicted)

408 files differ. The differing set is www **site content** accumulated over
twelve alphas: guide/blog/changelog/roadmap HTML prose, www-owned scripts
(`prism-init.js`, `logo-home.js`), `search-index.json`, icon assets removed
from the site, and `server/entry.js` (the server bundle embeds both the
drifted content and twelve alphas of framework hardening). This failure mode
is the one VERSION_PLAN ("Release evidence requirements") records
explicitly: _content drift between versions makes a fixed-ref byte
comparison meaningless as a recurring gate_ — the `v0.41.2` comparison was
run once as alpha.1 release evidence and passed then
([`v0.42.0-alpha.1.md`](./v0.42.0-alpha.1.md): "a pure-static project's
public output is byte-identical to the 0.41.2 build").

### 1c. Baseline `v0.42.0-alpha.12` — FAIL (content drift since the tag)

62 files differ, same category: the post-alpha.12 www site-progress train
(`3f02605c`, `a067628b`, `8b6f2938` — stable-claim fixes, zh parity for 14
pages, capability docs) edited www source after the tag. No diff is in a
framework-emitted artifact shape; all are page prose, sitemap, island
manifest page metadata, and the server bundle embedding them.

**Conclusion for the tool half:** the fixed-ref byte comparison cannot
re-prove the 0.41.x freeze at TP-6 — www is a living docs site, exactly the
limitation VERSION_PLAN anticipated. What the tool does prove today is
build determinism (1a). The zero-cost upgrade claim therefore rests on the
consumer-level proof below, where the _same_ site source is built against
both framework versions.

## 2. Consumer-level proof: same source, `0.41.2` → `0.42.0-alpha.12`

Method (reproduce):

```sh
# scaffold a pure-static project pinned to the 0.41.x line
deno run -A npm:@openelement/create@0.41.2 freeze041
cd freeze041 && deno install && deno task build
cp -R dist ../dist-0.41.2

# upgrade: specifiers 0.41.2 -> 0.42.0-alpha.12, clean reinstall, rebuild
sed -i '' 's/@0\.41\.2/@0.42.0-alpha.12/g' deno.json
rm -rf node_modules dist deno.lock
deno install && deno task build
cp -R dist ../dist-0.42.0-alpha.12
diff -rq ../dist-0.41.2 ../dist-0.42.0-alpha.12
```

The scaffold is the stock template: two static pages (`index`, `freshness`
with `renderIntent.revalidate: 300`), one island (`my-counter`), one
markdown content page, one API route. **No source file was edited between
the two builds** — the only change is the four `@openelement/*` version
specifiers in `deno.json`.

### Result

Byte-identical across the upgrade (11 of 17 files):

- All rendered pages: `index.html`, `freshness/index.html`
- All content artifacts: `search-index.json` (both copies),
  `isr-manifest.json`, `api/health.json`
- Static assets: `openelement-mark.svg` (all copies),
  `assets/_virtual_open-build-trigger-*.js`
- Both `island-manifests/*.json` **after stripping `builtAt`** (the same
  single normalization the freeze tool applies; with `builtAt` they differ
  only in that timestamp)

Differing files (6) — all framework-emitted runtime bundles, not site
output:

| File                                    | Cause                                                                                                                                                                                                                                     |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `client/islands/island-my-counter-*.js` | Element runtime internals changed across alpha.1–alpha.12 (props reflection rewrite, array/object attribute serialization, `collectPublicProps` dedup #621, attr-name allowlist #602); the content-hashed filename changes with the bytes |
| `client/islands/client.js`              | Island-loader codegen drift (a `.then()` normalization, `var t = e.default` refactor) plus the embedded island-bundle hash                                                                                                                |
| `client/.vite/manifest.json`            | Only the hashed island-bundle references                                                                                                                                                                                                  |
| `server/entry.js`                       | Server bundle embeds the hardened framework code                                                                                                                                                                                          |

### Reading

- **The upgrade is zero-cost**: no source change, no config change, no
  output-shape change; `deno install` + rebuild is the whole migration.
- **Every user-visible byte is identical**: HTML, content JSON, manifests
  (modulo the build timestamp) and assets match exactly.
- **Strict whole-tree byte-identity no longer holds at alpha.12** and cannot:
  the alpha.1 proof passed because the framework runtime was then
  byte-identical to 0.41.2; twelve hardening alphas (#539–#852) changed the
  emitted JS bundles legitimately. The TP-6 acceptance bullet ("upgrades
  with zero changes and byte-identical output") should be read as
  zero-change upgrade with byte-identical **content output** — the
  framework-runtime bundle drift recorded above is the honest boundary, and
  TP-6 should adopt this reading explicitly when accepting ADR-0122.

## 3. What guards the freeze going forward

- CI runs `check:static-output-freeze --self-check` on relevant changes
  (determinism = behavior-equivalent static output build over build, #600).
- The ADR-0119 freeze surface is untouched by the 0.42 line (ADR-0122 §7);
  any breaking change to it requires a major-version ADR.
- The full fixed-ref comparison stays a release-evidence tool, per
  VERSION_PLAN — re-run at `0.42.0` against the final alpha if TP-6 wants a
  same-source re-check, using the consumer method above for the 0.41.x
  comparison.

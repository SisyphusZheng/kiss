# v0.41.0 Deno-native npm Distribution + WC Interop

## Summary

v0.41.0 migrates openElement's package distribution channel from JSR to npm
while keeping the project Deno-native, hardens the signal-DOM architecture, and
proves cross-framework Web Components interoperability. Artifacts are built with
Deno 2.8+ `deno pack` and published to npm with provenance. The runtime-agnostic
boundary is hardened so browser-facing packages no longer rely on `Deno.*` APIs,
adapter-vite defaults to npm resolution, and a lightweight client runtime allows
openElement components to be consumed by third-party frameworks such as Deno
Fresh.

This release introduces no new server/data/cache/session primitives. It is staged
through four alphas and one beta before the stable tag.

## Changes

### Toolchain

- Bump minimum Deno version to 2.8.0 across docs, READMEs, and CI.
- Convert all internal `@openelement/*` imports from `jsr:` to `npm:` in root
  and `packages/*/deno.json`.
- Add `deno task pack` and `deno task publish:npm` that pack and publish the
  11-package graph in dependency order.
- Add `deno task pack:dry-run` for CI validation of tarball output.
- Clean up workspace import maps so internal specifiers resolve to npm names.
- Add pure-ESM / pure-ECMAScript quality gates (`publint`,
  `attw --profile esm-only`, and custom static scans) to the release pipeline.

### Runtime-agnostic Boundaries

- ~~Move `FileIsrCache` from `@openelement/core/isr` to
  `@openelement/ssg/file-isr-cache`; keep `MemoryIsrCache` and the cache
  interface in `core`.~~ Superseded by architecture audit cleanup: `FileIsrCache`
  was removed after audit confirmed no production callers. `MemoryIsrCache`
  remains the reference implementation.
- ~~Change `router/src/page-loader.ts` `loadPage()` to accept raw markdown text
  instead of reading files with `Deno.readTextFile`.~~ Superseded by cleanup:
  `router/src/page-loader.ts` was removed during architecture audit. Raw markdown
  rendering remains available in `@openelement/content`.
- Add `tools/check-deno-api-free.ts` and a `deno task deno-api:check` gate that
  fails if `core/element/ui/protocol/signal/router/app` source files use
  `Deno.*`.

### Signal-DOM Architecture

- Extract hydration lifecycle into `@openelement/core/hydrate` as a standalone
  entry point (`HydrationScope`).
- Split `jsx-render-dom.ts` (pure translator emitting descriptors) from
  `binding-activation.ts` (effect lifecycle owner).
- Replace the central `BindingDescriptor` switch with an internal registry of
  small binding factories (`bindText`, `bindAttr`, etc.).

### Cross-Framework Web Components

- Prove Lit, Shoelace, and Material Web Components render, hydrate, and remain
  interactive inside an openElement app.
- Document the interop contract between openElement components and standard
  Custom Elements.

### External Framework Consumption

- Provide a lightweight client runtime (`@openelement/core/hydrate`) so
  openElement components can be consumed by Deno Fresh and other third-party
  frameworks.

### Adapter-vite and Starter Template

- Default `createOpenJsrPackageResolverPlugin` to npm mode: skip virtual-module
  source fetching and let Vite resolve `@openelement/*` from `node_modules`.
- Keep JSR source resolution available via explicit `registry: 'jsr'` option.
- Update `@openelement/create` to emit `npm:@openelement/*` imports and resolve
  remote package versions from the npm registry instead of JSR.

### Release Flow

- Replace JSR publish with `deno pack` + `npm publish --provenance` in
  `tools/autoflow/release.ts`.
- GitHub Actions `autoflow-release.yml` uses `actions/setup-node` and
  `secrets.NPM_TOKEN` for provenance publishing.
- Keep dual npm/JSR publishing; JSR acts as a strictness signal, npm as the
  primary distribution channel.
- Keep `jsr-consumer-monitor.yml` and `wait-jsr-release-metadata.ts` as
  historical observation tools, not release gates.

### Consumer Smoke Coverage

- Add post-publish consumer smoke for Node ESM, Deno `npm:`, jsDelivr CDN, and
  Nitro Node/Workers output.
- Add third-party WC smoke for Shoelace and Material Web Components.
- Add Fresh example smoke for openElement component hydration.

## Verification

- `deno task deno-api:check` passes.
- `deno task pack:dry-run` succeeds for all 11 packages.
- `deno task test` passes.
- No `jsr:@openelement/` or `@jsr/openelement__*` specifiers remain in product
  code or generated tarballs.
- GitHub Actions `autoflow-release.yml` successfully publishes to npm with
  provenance and to JSR as a secondary channel.
- npm consumer smoke passes for Node ESM and Deno `npm:`.
- jsDelivr browser-safe export smoke passes.
- Pure-ESM / pure-ECMAScript gates pass for every npm artifact.
- Third-party WC libraries render and hydrate inside an openElement app.
- A Fresh example project SSRs and hydrates an openElement component.

## Migration

Install commands changed from JSR to npm:

```diff
- import { ... } from "jsr:@openelement/core@^0.40.8";
+ import { ... } from "npm:@openelement/core@^0.41.0";
```

Already published JSR versions remain available, but the current line is
published to npm only. Update lockfiles and import maps to use `npm:`
specifiers for `@openelement/*` packages.

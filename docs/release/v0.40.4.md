# v0.40.4 Release Plan

## Summary

v0.40.4 completes the pre-publish packaged starter smoke introduced in v0.40.3.
The first v0.40.3 publish attempt showed that checking for import-map key
coverage is not enough: Deno must also be able to resolve the mapped specifier.

## Changes

- Replace the invalid generated starter `hono/` prefix mapping with explicit
  Hono subpath mappings:
  - `hono/cors`
  - `hono/logger`
  - `hono/request-id`
  - `hono/secure-headers`
- Extend `consumer:packaged` so it runs real
  `deno info --config <generated-deno-json> dist/server/entry.js` after local
  build.
- Keep the bare-import scan as a readable diagnostic before the real Deno
  resolution check.
- Bump the package line to `0.40.4` because the generated starter template
  changed and JSR `0.40.3` is immutable.

## Acceptance

- `consumer:packaged` catches missing import-map keys.
- `consumer:packaged` catches invalid import-map values.
- Main `Publish to JSR` publishes v0.40.4 and post-publish consumer smoke
  passes.

## Verification

- `deno test --allow-read --allow-write --allow-run --allow-env --allow-net packages/create/__tests__/cli.test.ts`
- `deno task consumer:packaged`
- `deno task consumer:local`
- `deno task autoflow:ci`
- `deno task publish:dry-run`

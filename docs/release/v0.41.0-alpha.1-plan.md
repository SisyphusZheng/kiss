# v0.41.0-alpha.1 Version Plan - Audit-Driven Slimming

## Objective

Apply the over-engineering audit findings to `dev` as the first v0.41 alpha.
Delete speculative surfaces, collapse single-implementation abstractions, remove
unused dependencies, fold duplicate utilities, and restore `@openelement/protocol`
as a minimal type-only contract layer. Primary goal is reducing maintenance
surface; runtime quality gains are welcome side effects.

No behavioral regression for retained public surfaces. Intentionally removed
speculative/deprecated APIs (e.g. `@prop()` decorator runtime, `ReactiveHost`,
protocol interfaces with single implementations) are documented as accepted
breaking changes for an alpha release.

Net result: 11 packages (from 10 after initial protocol deletion back to 11
with type-only protocol layer), ~2,000 net lines removed, 3 runtime dependencies
removed (`alien-signals`, `esbuild`, `typescript`).

## Governance

- Autoflow3 remains the release control plane and is **out of scope** for this
  cleanup (needed for Codeberg sync), but ADR-0108 npm tasks must be verified
  end-to-end through Autoflow3 or equivalent CI before v0.41.0-alpha.1 is marked
  releasable.
- All cuts are source-only unless tests directly test the removed surface.
- Deleted tests must be matched by equivalent coverage on retained code or
  acknowledged as accepted loss for removed features.

### v0.41.0-alpha.1 - Framework Architecture Review

Comprehensive review of the rendering pipeline and signal-to-DOM binding:

**Rendering paths — 4 exist, all necessary:**

| Path                   | Mechanism                                                                  | Purpose                                     |
| ---------------------- | -------------------------------------------------------------------------- | ------------------------------------------- |
| A. Fine-grained effect | `effect(() => el.setAttribute())`                                          | Signal prop → DOM attr update, no re-render |
| B. Signal → TextNode   | `effect(() => textNode.textContent = sig.value)`                           | JSX signal children expression              |
| C. Full re-render      | `render()` → `while(root.firstChild) root.removeChild()` → `renderToDom()` | Initial mount + `this.update()`             |
| D. DSD hydration       | `querySelectorAll('[data-signal]')` → `effect()`                           | SSR → client signal binding                 |

**Framework confirms user understanding:** VNode is an intermediate representation
(5 frozen fields: `tag`, `props`, `children`, `key`, `ref`), NOT a virtual DOM.
No diff algorithm, no reconciliation, no keyed child matching. Signal changes drive
DOM updates directly via `effect()` callbacks — no VNode involvement.

**Identified redundancies:**

- **Double signal binding** — `class={this.#signal}` + `data-signal-attr` on the same
  element cause two subscription paths that collide: signal change triggers full
  `render()` which replaces the DOM element, while `data-signal-attr` tries to update
  the attribute in-place. Result: `onClick` handler lost on re-render.
  Fix in `open-search.tsx`: use static `class='overlay'` + only `data-signal-attr`.
- **Signal→DOM binding logic duplicated** — Path A (`applyProps` + `effect` in
  `jsx-render-dom.ts`) and Path D (`hydrateSignals` in `open-element-hydration.ts`)
  both bind signals to DOM but from different starting points (VNode vs SSR markers).
  Could be unified by making Path D call `renderToDom` instead of manual `effect()`.
- **`adoptedStyleSheets` for global tokens** — `openPropsTokenSheet` and
  `daisyClassSheet` are adopted into every component's shadow root, but the same
  CSS is already injected as page-level `<style>` by `vite.config.ts`. The
  duplicate adoption causes Safari's adoptedStyleSheets bug (`:host([data-theme])`
  does not recompute when `data-theme` attribute changes).

### v0.41.0-alpha.1 - Progress on AdoptedStyleSheets Safari Bug

Safari/WebKit bug: `adoptedStyleSheets` containing `:host([data-theme])` selectors
do not recompute when the host element's `data-theme` attribute changes via JS.
This affects themed colors (`--bg-canvas`, `--surface-*` etc.) inside shadow DOM.

Attempted workarounds (all failed for the surface colors test):

- JS style.setProperty() on documentElement — Safari still uses stale adoptedSheet values
- Forcing style recalculation via offsetHeight read — no effect
- Re-assigning `adoptedStyleSheets = [...sheets]` — does not trigger recompute

**Current fix applied:**

- [x] `open-theme-toggle`: removed `openPropsTokenSheet` from `static styles`.
      The token CSS custom properties are already injected as page-level `<style>`
      by `vite.config.ts` and cascade through shadow DOM naturally. The component
      only adopts its own component-specific sheet.

**Long-term solutions (tracked for future):**

| Solution                                                            | Effort               | Effect                                                                            |
| ------------------------------------------------------------------- | -------------------- | --------------------------------------------------------------------------------- |
| Remove token sheets from all component `static styles`              | Medium               | All components inherit theme tokens from page-level CSS, bypassing the Safari bug |
| Switch affected components to `renderMode = 'light'`                | Small per component  | No adoptedStyleSheets at all, but loses style encapsulation                       |
| Use CSS `light-dark()` function instead of `[data-theme]` selectors | Large (CSS refactor) | Modern standard, works in all browsers, eliminates the selector dependency        |
| Unify signal binding Paths A and D (make D call `renderToDom`)      | Medium               | Reduces code duplication, simplifies maintenance                                  |

## Grilling clarifications (2026-06-23)

The following wording/assumption clarifications emerged from a `/grilling` session
after the main implementation was complete. They are recorded here so future
version plans do not inherit the original fuzziness.

1. **"Scope is slimming only; correctness and behavior stay unchanged"**
   - Original implication: no observable change at all.
   - Clarification: the alpha intentionally removes speculative/deprecated public
     APIs (`@prop()` decorator runtime, `ReactiveHost`, single-implementation
     protocol interfaces). The correct framing is "no behavioral regression for
     retained public surfaces; removed APIs are accepted breaking changes."

2. **"Convert internal `@openelement/*` imports from `jsr:` to `npm:`"**
   - Original implication: rewrite workspace source imports.
   - Clarification: workspace source already uses bare specifiers resolved by
     Deno workspace. No internal `jsr:@openelement/*` imports existed to convert.
     The task meant: ensure npm is the primary distribution channel and no
     internal references remain on the JSR path.

3. **Autoflow3 out of scope**
   - Original implication: release control plane is untouched.
   - Clarification: ADR-0108 npm tasks are CLI-complete, but v0.41.0-alpha.1 is
     not releasable until `autoflow:release` (approved-release, not patch-release)
     has executed the npm pack/publish pipeline end-to-end at least once.
     `deno task autoflow:release --dry-run --approved-plan ADR-0105/v0.40.x-cleanup-train --to 0.41.0-alpha.1` passed all 27 release gates.

4. **`@openelement/core` subpath split (`static`/`hydrate`/`csr`)**
   - Original implication: splitting alone reduces static-component cost.
   - Clarification: current UI/www consumers still import from the root entry.
     The split is architecturally sound but needs at least one real static-only
     user before v0.42, otherwise it should be reconsidered.

5. **Content writer modules inlined into `packages/content/src/index.ts`**
   - Original implication: fewer files is always better.
   - Clarification: inlined writers are acceptable while `index.ts` stays under
     ~400 lines and serialization remains simple. A `ponytail:` threshold comment
     marks the re-extraction trigger.

6. **Protocol package reversal (delete → restore as type-only)**
   - Lesson: future cleanups should compress a protocol layer to type-only first,
     then evaluate deletion, rather than deleting the whole layer and restoring
     it later.

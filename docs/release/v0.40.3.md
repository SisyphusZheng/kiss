# v0.40.3 Release Plan

## Summary

v0.40.3 closes the release-process gap exposed by v0.40.0 and v0.40.1: generated
starter dependency gaps must fail before immutable JSR publish, not after it.

The release train now adds a packaged starter smoke gate that validates the
generated starter's original import map against the SSR bundle produced during a
local build. This catches missing bare imports such as `marked` and
`@preact/signals-core` before a version is published.

## Changes

- Bump the package line to `0.40.3` because the generated starter template
  changed and JSR `0.40.2` is immutable.
- Add `deno task consumer:packaged`.
- Extend `tools/consumer-local.ts` with `--packaged-import-map-check`.
- Preserve the generated starter's original `deno.json` import map before local
  source aliases are injected.
- After local build, scan `dist/server/entry.js` for bare imports.
- Fail if any bare import from the generated SSR bundle is not resolvable from
  the original starter import map.
- Add the generated starter `hono/` import-map prefix so Hono subpath imports
  used by the build/runtime stack are resolvable before publish.
- Add `consumer:packaged` to AutoFlow3 push, ci, and release tiers for starter,
  app, adapter, content, signal, SSG, consumer-smoke, and root config changes.

## Acceptance

- Missing generated starter dependencies fail before publish.
- The gate is owned by AutoFlow3, not by ad hoc post-release workflow logic.
- `consumer:local` still runs the full local source + Nitro smoke.
- `consumer:packaged` is the faster publish-safety check for generated starter
  import-map completeness.
- Main `Publish to JSR` publishes v0.40.3 and post-publish consumer smoke
  passes.

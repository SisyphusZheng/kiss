# OpenElement v0.41.0-alpha.15 — Adoption Qualification and Stable Readiness

## Status

- Plan state: approved execution baseline
- Source and npm entry line: `0.41.0-alpha.14`
- Target line: `0.41.0-alpha.15`
- Stable candidate prepared by this work: `0.41.0`
- Stable release is not pre-authorized by this plan

## Outcome sought

Alpha.15 must answer one question with durable evidence: can the existing
five-package OpenElement product be frozen as `0.41.0`, or does real adoption
still require a breaking alpha correction?

The release combines four bounded outcomes:

1. supported GitHub Actions run on the current Node 24 action runtime;
2. current docs and version gates cannot drift behind registry truth;
3. external adopters complete the published path without private instructions;
4. the public five-package interface has a reviewable compatibility baseline.

## Interface policy

No interface change is planned. Alpha.15 is the last intended observation line
before `0.41.0`; therefore a breaking correction is permitted only when backed
by pilot evidence, an ADR, migration guidance and compatibility tests. No new
package, JSR publication or speculative runtime seam is authorized.

## Release blockers

- Missing real participants or fabricated pilot evidence.
- Any unresolved P0 or unacknowledged P1 pilot finding.
- Current docs disagreeing with source, npm or active target.
- Action workflows depending on a blocking unreliable external review.
- Public export/declaration drift without an approved decision.
- Any failed required browser, runtime, packaged or post-publish consumer.
- npm, tag, release body or evidence disagreement.

## Completion definition

Alpha.15 is complete only when P1–P8 are checked with links to repository or
GitHub evidence. Publishing npm artifacts alone is insufficient. Readiness for
`0.41.0` is a separate decision and requires a separate approved stable plan.

# v0.41.0-alpha.5 Version Plan - SPA Mode + Deno Desktop Reader Proof

## Objective

Prove that openElement can power single-page applications and target a lightweight
desktop environment via Deno Desktop (Deno canary). The proof app is a
WeRead-style desktop reader backed by local/open content fixtures, not by
WeRead private APIs or copyrighted account data. The reader validates the app
substrate: navigation, local state, reading settings, annotations, and desktop
window ergonomics without requiring a server or pre-rendered HTML.

This release is a prerequisite for the alpha.6-alpha.7 Mastodon/GoToSocial
practice train. Alpha.6 should validate read-only real-network data; alpha.7
should validate authenticated mutations. Neither should pull those concerns
back into alpha.5.

## Governance

- No public API breakage unless explicitly listed in **Accepted breaking changes**.
- All changes must pass the standard CI gate set.
- E2E regression is a release blocker.

## Workstreams

### v0.41.0-alpha.5 - SPA Mode Core

- [x] Add `defineApp({ mode: 'spa' })` to `@openelement/app`.
- [x] Implement a client-side router in `@openelement/router` and wire it into
      `@openelement/app`:
  - History-based navigation (`pushState`/`popstate`).
  - `auto` mode that uses history on HTTP(S) and hash navigation for `file://`
    and legacy embedded contexts.
  - Route params, query strings, and guards without a server route manifest.
- [x] Runtime bootstrap:
  - Mount the app shell into a plain DOM node (no DSD template required).
  - Support full client-side render on first load.
  - Dispose and remount on hot reload during development.
- [x] SPA data layer:
  - In-memory loader/action data context.
  - Optional async route guards.

Implementation notes:

- `SpaAppOptions.routerMode` can explicitly select `history`, `hash`, or `auto`;
  the default is `auto`.
- The SPA layer does not register its own `popstate` listener. The router owns
  browser navigation events and calls an `onChange` callback after it rematches,
  avoiding duplicate renders on back/forward navigation.
- Query and route params are accumulated in null-prototype records so URL query
  keys cannot write through object prototypes.

Deferred from alpha.5:

- Hydrating an existing SSR shell in hybrid mode.
- Lazy route loading as a first-class app API.

### v0.41.0-alpha.5 - Desktop Shell Baseline (Deno Desktop)

When Deno canary ships with native `deno desktop` support, validate SPA mode
targeting a Deno-powered desktop window instead of Tauri 2 / Electron.

- [x] Create `examples/deno-desktop-spa/`.
- [x] Keep browser imports resolvable in the served HTML via an import map
      instead of relying on bare npm specifiers in native browsers.
- [ ] Deno canary desktop compile remains evidence-gated by Deno canary
      availability on the release runner.

Tauri 2 / Electron / stable Deno desktop are deferred to v0.42 or later; Deno Desktop is the preferred
lightweight shell for the Deno-native ecosystem.

### v0.41.0-alpha.5 - Desktop Reader Practice App

Add a concrete desktop reader project that makes the shell proof product-shaped
instead of demo-shaped.

- [ ] Create `examples/deno-desktop-reader/` as the primary alpha.5 desktop
      practice app.
- [ ] Keep `examples/deno-desktop-spa/` as the minimal smoke fixture; the reader
      is the richer dogfood target.
- [ ] Use local/open fixtures only:
  - `books.json` or equivalent metadata.
  - Short public-domain or synthetic chapter text.
  - No WeRead private API, account cookies, scraping, or copyrighted book
    content.
- [ ] Reader routes:
  - `/` bookshelf.
  - `/books/:id` reading surface.
  - `/notes` annotations/highlights.
  - `/search` local search.
  - `/settings` reading preferences.
- [ ] Reader interaction proof:
  - Persist reading progress, theme, font size, and line height through a
    browser-native storage API.
  - Add notes/highlights through SPA actions or equivalent app-local mutation
    flow.
  - Support keyboard navigation for next/previous chapter and settings toggles.
  - Exercise route params, query strings, loader/action data, empty states, and
    error states in the desktop shell.
- [ ] CI smoke:
  - Open the generated reader app in Chromium or Deno Desktop when available.
  - Verify bookshelf render, open-book navigation, settings persistence, and
    note creation.
  - Keep Deno Desktop canary compile evidence non-blocking until the runner can
    install the required canary toolchain reliably.

## Acceptance

- [x] `defineApp({ mode: 'spa' })` boots an openElement app without SSR.
- [x] Client-side router supports history, hash, and auto navigation.
- [ ] Deno Desktop reader validates SPA mode in a product-shaped desktop
      context, with native desktop compile evidence pending Deno canary support.
- [ ] SSG/ISR features remain cleanly out of scope for SPA mode.
- [ ] All verification gates pass.

## Non-Goals

- No Tauri 2 / Electron integration (deferred to v0.42+).
- No attempt to make SSG/ISR work inside SPA mode.
- No full Preact framework integration — only island-level bridge (see alpha.4).
- No WeRead private API integration, login/session reuse, scraping, or
  copyrighted book content.
- No Mastodon/GoToSocial API integration in alpha.5; that practice train starts
  at alpha.6.

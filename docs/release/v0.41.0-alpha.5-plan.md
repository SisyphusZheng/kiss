# v0.41.0-alpha.5 Version Plan - SPA Mode + Desktop Shell Proof

## Objective

Prove that openElement can power single-page applications inside desktop-style
shells (Tauri 2, Electron, Capacitor-style embedded WebViews). openElement's
default remains SSG/SSR-first, but alpha.5 adds a first-class `appMode: 'spa'`
option and a client-side router so the same component model works when there is
no server and no pre-rendered HTML.

This release is a prerequisite for the separate GoToSocial/Mastodon desktop
client project, which depends on SPA mode plus v0.42.0-0.45.0 server/data/forms/auth
primitives.

## Governance

- No public API breakage unless explicitly listed in **Accepted breaking changes**.
- All changes must pass the standard CI gate set.
- E2E regression is a release blocker.

## Workstreams

### v0.41.0-alpha.5 - SPA Mode Core

- [ ] Add `appMode: 'spa'` to the openElement app config.
- [ ] Implement a client-side router in `@openelement/router` or
      `@openelement/app`:
  - History-based navigation (`pushState`/`popstate`).
  - Optional hash-based navigation for `file://` and legacy embedded contexts.
  - Route params, query strings, and guards without a server route manifest.
- [ ] Runtime bootstrap:
  - Mount the app shell into a plain DOM node (no DSD template required).
  - Support full client-side render on first load.
  - Support hydrating an existing SSR shell if the same app is later used in
    hybrid mode.
  - Dispose and remount on hot reload during development.
- [ ] SPA data layer:
  - In-memory loader/action data context.
  - Optional async route guards.
  - Lazy route loading.

### v0.41.0-alpha.5 - Desktop Shell Examples

- [ ] Create `examples/tauri-spa/`:
  - Minimal Tauri 2 project using openElement in SPA mode.
  - Verify navigation, route params, signal-driven updates, and window-level
    events.
- [ ] Optionally create `examples/electron-spa/` for coverage.

### v0.41.0-alpha.5 - Documentation

- [ ] Write `docs/integrations/spa-mode.md`.
- [ ] Document differences between SSG/SSR mode and SPA mode.
- [ ] Document recommended disposal patterns for desktop shells.

## Acceptance

- [ ] `appMode: 'spa'` boots an openElement app without SSR.
- [ ] Client-side router supports history and optional hash navigation.
- [ ] Tauri 2 example project mounts, navigates, and updates signal-driven UI.
- [ ] SSG/ISR features remain cleanly out of scope for SPA mode.
- [ ] All verification gates pass.

## Non-Goals

- No server primitives.
- No official mobile shell adapter.
- No attempt to make SSG/ISR work inside SPA mode.

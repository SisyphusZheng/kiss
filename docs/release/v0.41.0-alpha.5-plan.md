# v0.41.0-alpha.5 Version Plan - SPA Mode + Deno Desktop Reader Proof

## Objective

Prove that openElement can power single-page applications and target a lightweight
desktop environment via Deno Desktop (Deno canary). The proof app is a
WeRead-style desktop reader backed by local/open content fixtures, not by
WeRead private APIs or copyrighted account data. The reader validates the app
substrate: navigation, local state, reading settings, annotations, and desktop
window ergonomics without requiring a server or pre-rendered HTML.

This release is a prerequisite for the alpha.6-alpha.7 Mastodon/GoToSocial
practice train. Alpha.6 should validate read-only real-network data; alpha.7
should validate authenticated mutations. Neither should pull those concerns
back into alpha.5.

## Governance

- No public API breakage unless explicitly listed in **Accepted breaking changes**.
- All changes must pass the standard CI gate set.
- E2E regression is a release blocker.

## Workstreams

### v0.41.0-alpha.5 - SPA Mode Core

- [x] Add `defineApp({ mode: 'spa' })` to `@openelement/app`.
- [x] Implement a client-side router in `@openelement/router` and wire it into
      `@openelement/app`:
  - History-based navigation (`pushState`/`popstate`).
  - `auto` mode that uses history on HTTP(S) and hash navigation for `file://`
    and legacy embedded contexts.
  - Route params, query strings, and guards without a server route manifest.
- [x] Runtime bootstrap:
  - Mount the app shell into a plain DOM node (no DSD template required).
  - Support full client-side render on first load.
  - Dispose and remount on hot reload during development.
- [x] SPA data layer:
  - In-memory loader/action data context.
  - Optional async route guards.

Implementation notes:

- `SpaAppOptions.routerMode` can explicitly select `history`, `hash`, or `auto`;
  the default is `auto`.
- The SPA layer does not register its own `popstate` listener. The router owns
  browser navigation events and calls an `onChange` callback after it rematches,
  avoiding duplicate renders on back/forward navigation.
- Query and route params are accumulated in null-prototype records so URL query
  keys cannot write through object prototypes.

Deferred from alpha.5:

- Hydrating an existing SSR shell in hybrid mode.
- Lazy route loading as a first-class app API.

### v0.41.0-alpha.5 - Desktop Shell Baseline (Deno Desktop)

When Deno canary ships with native `deno desktop` support, validate SPA mode
targeting a Deno-powered desktop window instead of Tauri 2 / Electron.

- [x] Create `examples/deno-desktop-spa/`.
- [x] Keep browser imports resolvable in the served HTML via an import map
      instead of relying on bare npm specifiers in native browsers.
- [ ] Deno canary desktop compile remains evidence-gated by Deno canary

Tauri 2 / Electron / stable Deno desktop are deferred to v0.42 or later; Deno Desktop is the preferred
lightweight shell for the Deno-native ecosystem.

### v0.41.0-alpha.5 - Desktop Reader Practice App

Add a concrete desktop reader project that makes the shell proof product-shaped
instead of demo-shaped.

#### Product Intent

The reader is the alpha.5 dogfood app. It should feel like a small modern
desktop reading product inspired by WeRead ergonomics, while staying legally and
technically independent from WeRead.

- Goal: prove openElement can support a real desktop SPA loop, not only a
  counter demo.
- Scope: bookshelf, reading surface, notes/highlights, local search, settings,
  progress persistence, and desktop keyboard ergonomics.
- Boundary: no WeRead private API, login/session reuse, scraping, DRM bypass,
  or copyrighted book content. All fixtures must be synthetic or clearly
  public-domain/open licensed.
- Renderer constraint: alpha.5 reader route components should return real DOM
  `Node`/`DocumentFragment` values, matching the current SPA contract. Do not
  add a full Preact/React/Vue/Svelte adapter or a broad renderer abstraction in
  this workstream.

#### Differentiation Strategy

The reader should not compete by cloning WeRead's network, social graph, or
bookstore. Its alpha.5 differentiation is **local-first reading into a personal
knowledge base**:

- Local-first: books, progress, settings, notes, and highlights work without an
  account or remote service.
- Reader-to-notes flow: every highlight can become a durable note with source
  metadata, quote, chapter, and backlink.
- Open content format: fixture books and exported notes are Markdown/JSON, not a
  proprietary database.
- Desktop ergonomics: keyboard-first navigation, stable reading measure, and
  fast local search matter more than social ranking or bookstore discovery.
- Framework proof: the app exists to stress SPA mode, local persistence,
  route params/query strings, forms/actions, and Deno Desktop packaging.

This gives the practice app a distinct shape:

```text
WeRead-like inspiration: polished reading UX, bookshelf, notes.
openElement reader differentiation: local-first, Markdown-native, Obsidian-friendly,
desktop dogfooding, no platform lock-in.
```

#### Obsidian Compatibility

Alpha.5 should plan for Obsidian interop without turning the reader into an
Obsidian plugin.

- [ ] Add an export boundary in `storage.ts` or a sibling `export.ts` that can
      convert notes/highlights into Markdown files.
- [ ] Use Obsidian-friendly Markdown conventions:
  - YAML frontmatter for `bookId`, `bookTitle`, `author`, `chapterId`,
    `createdAt`, and tags.
  - Blockquotes for highlighted text.
  - A short user note below the quote.
  - Wiki links where useful, e.g. `[[Book Title]]`.
  - Stable anchors or source links back to the reader route, e.g.
    `open-reader://books/book-id?chapter=chapter-id` as a future placeholder.
- [ ] Keep export one-way in alpha.5:
  - Reader → Markdown vault export is in scope.
  - Live bidirectional sync is not in scope.
  - Obsidian plugin APIs are not in scope.
- [ ] Treat the vault path as a user-selected local path only when Deno Desktop
      can expose a safe file picker. Until then, generate downloadable Markdown
      or write to an example-local `exports/` folder during smoke tests.
- [ ] Add a smoke fixture that creates a note and verifies the generated
      Markdown contains frontmatter, quote, note body, and backlink metadata.

#### Project Layout

- [ ] Create `examples/deno-desktop-reader/` as the primary alpha.5 desktop
      practice app.
- [ ] Keep `examples/deno-desktop-spa/` as the minimal smoke fixture; the reader
      is the richer dogfood target.
- [ ] Add the following planned structure:

```text
examples/deno-desktop-reader/
  deno.json
  README.md
  main.ts
  app/
    index.html
    reader.ts
    routes.ts
    storage.ts

  fixtures/
    books.json
    books/
      public-domain-sample.md

  __tests__/
    storage.test.ts
    routes.test.ts
```

- [ ] `main.ts` owns the Deno Desktop/Deno.serve host glue and serves static
      browser assets with a native import map.
- [ ] `app/reader.ts` boots `defineApp({ mode: 'spa', routerMode: 'auto',
      routes })` and mounts into `#root`.
- [ ] `app/routes.ts` defines DOM-returning route components and their
      loader/action functions.
- [ ] `app/storage.ts` is the only persistence boundary for progress, settings,
      and notes. It should prefer Web Platform APIs (`localStorage` first;
      IndexedDB only if localStorage becomes insufficient).
- [ ] `app/dom.ts` contains small DOM helpers for repeated UI creation. Keep it
      local to the example; do not promote a generic DOM DSL into packages.
- [ ] `fixtures/` contains only local/open reader content. Add a short license
      note in `README.md` for every fixture source.

#### Routes And User Flows

- [ ] `/` bookshelf:
  - Show book covers/titles/authors/progress.
  - Empty state if no books are available.
  - Continue-reading affordance opens the latest progress point.
- [ ] `/books/:id` reading surface:
  - Load a book by route param.
  - Render chapter text with stable readable measure.
  - Next/previous chapter buttons.
  - Persist progress on navigation and chapter changes.
  - Missing book id renders an in-app error state, not a blank page.
- [ ] `/notes` annotations/highlights:
  - List local notes grouped by book.
  - Link each note back to `/books/:id?chapter=...`.
  - Empty state when no notes exist.
- [ ] `/search` local search:
  - Query string drives the search term, e.g. `/search?q=memory`.
  - Search titles, authors, chapter headings, and local notes.
  - Verify `+` decoding through a smoke case such as `q=hello+world`.
- [ ] `/settings` reading preferences:
  - Theme: light, dark, sepia.
  - Font size.
  - Line height.
  - Reading width.
  - Persist settings and re-apply them after reload.

#### Data Model

- [ ] Define small example-local types:

```ts
interface ReaderBook {
  id: string;
  title: string;
  author: string;
  summary: string;
  coverTone: string;
  chapters: ReaderChapter[];
}

interface ReaderChapter {
  id: string;
  title: string;
  body: string;
}

interface ReaderProgress {
  bookId: string;
  chapterId: string;
  updatedAt: string;
}

interface ReaderNote {
  id: string;
  bookId: string;
  chapterId: string;
  quote: string;
  note: string;
  createdAt: string;
}

interface ReaderSettings {
  theme: 'light' | 'dark' | 'sepia';
  fontSize: number;
  lineHeight: number;
  measure: number;
}
```

- [ ] Keep IDs deterministic and fixture-friendly; no database or remote service
      in alpha.5.
- [ ] Use `structuredClone`/JSON serialization only inside `storage.ts`.
- [ ] Storage corruption should fall back to defaults and surface a warning in
      the UI or console; it must not crash app boot.

#### Interaction Requirements

- [ ] Keyboard:
  - `ArrowRight` / `ArrowLeft` for next/previous chapter.
  - `Cmd/Ctrl+F` focuses local search.
  - `Cmd/Ctrl+,` opens settings.
- [ ] Reading state:
  - Opening a book restores the last chapter.
  - Changing chapter updates progress.
  - Settings apply live without route reload.
- [ ] Notes:
  - Add a note from the reading surface through a form/action path.
  - Note creation updates `/notes` without requiring a full app reload.
  - Notes persist across reload.
- [ ] Navigation:
  - Use router params for `/books/:id`.
  - Use query strings for `/search?q=...` and optional chapter selection.
  - Exercise `router.navigate()` and `router.replace()` through visible UI.
- [ ] Desktop ergonomics:
  - Window size defaults to a reader-friendly desktop layout.
  - Text does not overflow at narrow desktop widths.
  - No marketing hero; first screen is the bookshelf.

#### Reader Non-Goals

- No WeRead private API integration.
- No account login, cookie import, scraping, DRM, or copyrighted content.
- No EPUB/PDF parser in alpha.5; fixtures are Markdown/JSON only.
- No cloud sync.
- No mobile shell.
- No generic persistence package extraction.
- No broad renderer abstraction or framework adapter.

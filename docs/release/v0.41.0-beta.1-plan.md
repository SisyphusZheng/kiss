# v0.41.0-beta architecture plan - Interface Depth and Adoption Closure

> Planning stage name: `v0.41.0-beta.1`\
> First publishable candidate: `v0.41.0-beta.4`\
> Reason: npm `0.41.0-beta.1` through `.beta.3` are immutable partial package
> publishes and are not valid release candidates.

## Objective

Use the final pre-stable breaking window to turn the alpha.8 implementation
into one coherent, externally usable product. Beta is an implementation train,
not a validation-only rerun. It may remove packages, exports, compatibility
paths and architecture abstractions when doing so reduces caller knowledge and
makes the production path testable through a smaller interface.

The target product sentence is:

```text
openElement = Web Components-native application framework
authoring modes = Basic Element standalone + full application
default path = DSD/static-first + selective islands + Vite/Nitro
```

OpenElement does not claim general fullstack breadth before request-time data,
forms, sessions and cache are production interfaces. The v0.41 promise is a
static-first application path with API routes and proven deployment output.

Design evidence:
`docs/audit/2026-07-11-beta-architecture-product-audit.md`.

## Authority and change policy

- Breaking changes, package collapse, interface removal and architecture
  movement are explicitly allowed in this beta plan.
- This document authorizes design and issue creation. Package topology must be
  recorded in a beta ADR before implementation moves files.
- Replace old interfaces; do not retain indefinite compatibility layers merely
  because alpha published them.
- Every new seam requires two justified adapters. Otherwise keep the seam
  internal to the owning module.
- The module interface is the behavioral test surface. Tests on absorbed
  shallow modules are deleted after equivalent interface-level proof exists.

## Entry facts

- `v0.41.0-alpha.8` is the coherent current package line.
- Alpha.7 implementation work is closed except external pilot #390.
- The published `@openelement/create@0.41.0-alpha.8` fails because its required
  template `.gitignore` is absent from the tarball.
- The starter declares the 11-package implementation graph and resolves remote
  versions through the stale `latest` dist-tag.
- npm beta.1, beta.2 and beta.3 each contain only 8 of 11 packages; they are
  withdrawn historical artifacts.
- Alpha.8 release evidence is not finalized even though the release completed.
- Current static gates, lint, typecheck, graph, host-API and type-safety checks
  pass; beta preserves these strengths.

## Workstreams

### B1. Release and registry truth — P0

- Mark beta.1–beta.3 as withdrawn partial publishes in release/status docs.
- Make release execution resume safely when packages already exist.
- Finalize release evidence only after Git tag, GitHub prerelease, npm publish
  and post-publish smoke all agree.
- Add a verifier for version, package count, dist-tag, provenance, GitHub tag,
  release evidence and docs truth.
- Publish no beta until the intended complete graph can use `0.41.0-beta.4`.

Exit: one command reports coherent truth or fails with the exact divergent
surface.

### B2. Real installed starter — P0

- Fix template asset inclusion in the npm tarball.
- Resolve one coherent package manifest from the running CLI version/dist-tag;
  never combine `latest` with a prerelease CLI.
- Reduce generated imports to product packages only.
- Move JSX import source from `core` to a supported `element` or `app` subpath.
- Replace phase-specific build commands with `dev`, `check`, `test`, `build`,
  and `preview` product tasks.
- Execute the published CLI in a clean directory, then run the whole generated
  project lifecycle without workspace aliases.
- Run the same smoke using Deno's default dependency-age policy or document an
  intentional release waiting period.

Exit: a new user can complete the documented path without maintainer context,
manual version edits, internal imports or a monorepo checkout.

### B3. Product and package decision — P0

- Record one-product/two-adoption-mode positioning in an ADR.
- Validate the proposed five-package graph:
  `element`, `app`, `adapter-vite`, `create`, optional pruned `ui`.
- Use a migration spike to test absorption of:
  - `core` + `signal` + element contracts into `element` internals;
  - `router` + app contracts into `app` internals;
  - `content` + `ssg` + build contracts into `adapter-vite` internals;
  - public `protocol` into interfaces owned at concrete seams.
- Reject the collapse only with cycle, artifact-size, runtime-isolation, or
  independent-consumer evidence. “It already exists” is not evidence.

Exit: approved ADR, target graph, migration map and removal list.

### B4. Deep application interface — P0

- Make one app descriptor the input to routing, rendering, build and deploy.
- Wire or remove `createAppModel`, RouteGraph, RenderPipeline, RequestContext,
  AssetManifest, IslandManifest and DeploymentTarget abstractions. No exported
  architecture object may remain test-only.
- Fold route data access into the app interface; remove internal compatibility
  hooks and redundant global render state where explicit context suffices.
- Remove the legacy VNode SPA route path.
- Keep redirects, not-found behavior, route errors and navigation disposal
  observable through the app interface.

Exit: starter, website and dogfood all use the same application interface and
tests do not reach behind it.

### B5. Deep element/runtime interface — P0

- Make `@openelement/element` sufficient for JSX runtime, elements, styles,
  signals, DSD, hydration and errors.
- Fix Preact signals as an implementation detail until a second engine exists.
- Hide renderer, hydration, prop and signal internals from ordinary authors.
- Consolidate duplicate SSR/DOM render decisions behind one render interface.
- Remove deprecated JSON helpers and compatibility re-exports.
- Preserve third-party Custom Element admission and explicit client-only
  fallback behavior.

Exit: standalone element consumers and app authors never import `core`,
`protocol` or `signal`.

### B6. One production build module — P0

- Replace plugin-order shared mutation with a `buildApp()`-style deep module
  that returns typed artifacts.
- Keep Vite as the adapter around that build module.
- Internalize content scanning, SSG, generated data, manifests and Nitro glue
  unless a second adapter proves a public seam.
- Remove `openPipeline`, `openContent`, root Nitro compatibility exports,
  alpha-internal adapter subpaths and separate client/SSG author commands.
- Preserve Node and Workers output proofs and deterministic artifact evidence.
- Make build evidence phase-order independent: it must never report zero client
  JavaScript before later emitting an island bundle.

Exit: one author build command and one production code path produce all
validated artifacts.

### B7. UI and example pruning — P1

- Separate reusable UI primitives from website-only lab, standards, hero and
  brand artifacts.
- Remove unproven primitives or add real public consumers and browser tests.
- Merge overlapping dialog/modal/overlay behavior.
- Remove Daisy-era naming and duplicate `.js` export aliases.
- Reduce or remove `open-layout`; app navigation and product-specific shell
  behavior must not return to UI.
- Retire `deno-desktop-spa` and extract one desktop host harness shared by
  Reader and Mastodon.
- Make dogfood import packed/public product surfaces and remove `--no-check`.
- Make package-island discovery tree-shake to actually consumed declarations;
  do not bundle every UI export merely because the package is registered.

Exit: retained UI and examples each prove a product interface instead of
maintaining parallel application architecture.

### B8. Robustness and error semantics — P1

- Define observable outcomes for build, route, render, hydration, island and
  release failure.
- Remove silent fallbacks and source-order assumptions.
- Bound caches and long-running observers; retain stress evidence.
- Test cleanup/disposal, partial writes, interrupted builds, registry delay,
  retry/idempotency and corrupted manifest inputs.
- Keep security admission checks for generated code, URLs, HTML and package
  metadata.

Exit: every P0/P1 failure mode has a public outcome and an interface-level
test.

### B9. Test and gate realignment — P1

- Replace tests for absorbed shallow modules with tests at retained interfaces.
- Add published CLI create/build smoke as a release blocker.
- Run dogfood tests with typechecking.
- Keep Chromium as the fast PR gate and all three browsers as candidate gate.
- Retain 80% global line/branch/function thresholds, but add risk-based mutation
  or negative-path proof for render, build, navigation, package and release
  interfaces.
- Reduce source-text architecture assertions where behavior can be tested.
- Add an unused-public-export and duplicate-implementation report; require a
  human disposition rather than blind deletion.

Exit: gates detect the alpha.8 starter failure class and survive internal file
movement.

### B10. Adoption and release candidate — P0

- Rewrite README, website, guide, comparison, package docs and examples around
  the narrowed product position and retained imports.
- Complete external adopter pilot #390 on packed beta artifacts.
- Record setup time, failed steps, imports used, build output, deployment result
  and all required maintainer intervention.
- Close every pilot P0/P1 before publish.
- Publish the complete candidate as `0.41.0-beta.4` with the `beta` dist-tag and
  provenance.

Exit: npm, GitHub, docs, website, evidence and adopter report agree.

## Proposed sequence

| Phase | Workstreams | Outcome                                              |
| ----- | ----------- | ---------------------------------------------------- |
| 0     | B1, B2      | release truth and installed starter are trustworthy  |
| 1     | B3          | topology and positioning decision is approved        |
| 2     | B4, B5, B6  | app, element and build become deep modules           |
| 3     | B7, B8      | redundancy and robustness debt are removed           |
| 4     | B9          | tests move to retained interfaces                    |
| 5     | B10         | external adoption and beta.4 publish close the train |

Phases 2–3 may run in parallel only after B3 fixes the target seams. Do not
start UI polish or more features while B1/B2 remain red.

## Gate matrix

The existing release matrix remains the floor, with these additions:

- `consumer:create:published` — run the exact published CLI and generated app;
- `surface:unused-report` — public exports without production/external proof;
- `surface:product-imports` — starter/docs/dogfood use only product imports;
- `release:truth` — Git/npm/GitHub/docs/evidence convergence;
- `dogfood:packaged` — Reader and Mastodon use packed product artifacts;
- `test:e2e:browsers` — Chromium, Firefox and WebKit candidate proof;
- release interruption/resume integration test.

All existing format, lint, typecheck, graph, architecture, host-API,
type-safety, unit, coverage, critical-path, artifact, WC interop, Nitro, Deno,
Node and jsDelivr gates remain required unless the owning module is deleted.

## Exit criteria

- [ ] B1–B10 acceptance is complete with linked evidence.
- [ ] Published CLI creates and builds a project from a clean machine.
- [ ] Public package graph and exports match the approved beta ADR.
- [ ] Starter and dogfood contain no internal implementation imports.
- [ ] Every retained public interface executes on a production path.
- [ ] Identified compatibility/dead-code candidates are removed or explicitly
      retained with owner, consumer and removal policy.
- [ ] Release evidence is final and converges with Git, GitHub and npm.
- [ ] External adopter pilot #390 has no unresolved P0/P1 finding.
- [ ] `0.41.0-beta.4` is a complete provenance-backed package graph and owns the
      npm `beta` dist-tag.
- [ ] Stable `v0.41.0` requires no architecture or adoption work—only a version
      decision and final candidate rerun.

## Non-goals

- No ORM, database product, auth platform or plugin marketplace.
- No authenticated Mastodon mutations.
- No React/Vue/Svelte adapter expansion.
- No second build or signal adapter created solely to justify an abstraction.
- No new UI component count target.
- No server/data/forms/session/cache expansion before the retained v0.41
  interfaces are coherent.
- No compatibility promise for alpha-only internal imports.

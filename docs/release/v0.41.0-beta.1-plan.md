# v0.41.0-beta.1 Version Plan - Release-Candidate Validation

## Objective

Validate the alpha.7-frozen Web Components fullstack framework and Basic
Element product line as installed release-candidate artifacts. Beta.1 owns no
new implementation train: starter, architecture, public API, website,
positioning, trust, metadata, evidence, and external adoption work must close in
alpha.7 A7.01–A7.21 before this plan starts.

The product sentence remains:

```text
openElement = Web Components Fullstack Framework + Basic Element
supporting packages = Protocols + UI + official stack adapters
```

## Entry Criteria

- All 21 open alpha.7 slices are closed with acceptance evidence.
- The alpha.7 release plan, VERSION_PLAN, STATUS, ROADMAP, README files, npm
  metadata, and GitHub issue state agree.
- The published alpha.7 package line passes post-publish consumer verification.
- No P0/P1 external adopter finding remains unresolved.
- Package topology, default signal engine, browser baseline, and public adapter
  surface have approved decisions where required.

## Verification Dimensions

### A. Installed Starter

- Generate from the published npm prerelease in a clean directory.
- Run dev, build, test, SSR/SSG, island, and Node/Workers deployment paths.
- Prove the five-minute guide without monorepo aliases or maintainer context.

### B. Public Interface And Documentation

- Verify every documented import against installed package exports.
- Re-run English/Chinese doctrine, API reference, package surface, and version
  truth checks.
- Confirm public, advanced, internal, adapter, dogfood, and infrastructure
  labels match the alpha.7-frozen contract.

### C. Runtime And Browser Evidence

- Re-run Chromium, Firefox, and WebKit DSD/upgrade/navigation behavior.
- Re-run Node and Workers deployment proofs from the production BuildPlan.
- Re-run global and risk-weighted coverage gates, stress thresholds, and
  package artifact checks.

### D. Distribution And Trust

- Publish the candidate with provenance and the intended beta dist-tag.
- Inspect npm metadata and installed tarball contents after publication.
- Re-run dependency vulnerability, immutable-action, security-policy, and
  community-entry checks.

### E. Public Release Story

- Verify the website, sourced comparison, dogfood evidence, changelog, npm,
  GitHub prerelease, STATUS, and ROADMAP describe the same candidate.
- Confirm Reader and Mastodon remain evidence surfaces, not product lines.
- Confirm beta.1 introduces no new public feature or package.

## Exit Criteria

- The candidate passes the complete gate matrix from a clean checkout.
- Installed npm artifacts pass starter, runtime, browser, and consumer proofs.
- npm, GitHub, docs, website, and release evidence agree on version and status.
- No public surface or product behavior changed after alpha.7 freeze without a
  new approved plan.
- Stable v0.41.0 can be cut by changing version/release state rather than by
  completing deferred implementation work.

## Issue Policy

The former beta.1 implementation issues #236–#242, #272–#274, and #379–#390
are part of the alpha.7 A7.01–A7.21 train. Create a single beta.1 release-
candidate tracking issue only after the entry criteria pass; do not duplicate
those implementation slices.

## Non-Goals

- No server/data/forms/session/cache primitives.
- No authenticated Mastodon client work.
- No new package, registry, UI product, Studio, Hub, or plugin marketplace.
- No React/Vue/Svelte adapter expansion.
- No architecture debt carried forward merely to preserve the beta date.

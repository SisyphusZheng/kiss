# v0.42.0

**WC light fullstack, stable.** 0.42.0 freezes the request-time Application
Loop (ADR-0120) on top of the untouched 0.41.x static freeze (ADR-0119).
One route-to-interaction loop — load, DSD render, progressive form, action,
error/redirect, revalidation — works end-to-end **without JavaScript**, and
upgrades progressively when JavaScript is available. Freeze scope and
non-goals: ADR-0122 (accepted 2026-08-14, TP-6).

## What 0.42.0 adds over 0.41.x

**The request-time application loop**

- `definePage` routes gain `loader` / `action` (and named `actions`) with a
  Web-standard `Request` context; `useLoaderData()` / `useActionData()`
  read the data channel in renders.
- The `fail()` / `redirect()` algebra: action failures re-render with 422 +
  error data; success follows Post/Redirect/Get with a 3xx whitelist;
  `notFound()` from any render produces a real 404 status.
- PRG revalidation semantics: the action always precedes the loader re-run.
- No-JavaScript baseline: every protocol path degrades to native HTML —
  forms post natively, errors render server-side.
- RFC 9457 problem+json on the fetch action channel
  (`x-openelement-action`).

**Progressive enhancement and the morph client**

- `data-open-enhance` forms morph the response into the page without a full
  navigation; the morph client is component-model-agnostic (id-keyed
  alignment, DSD template descent) and preserves focus, scroll, and
  form-control state across updates.
- Pre-hydration clicks are captured and replayed once the island hydrates.
- The enhanced and native channels are symmetric — same action, same
  semantics, two transports.

**Security floor**

- Fail-closed CSRF same-origin default on generated action POSTs
  (Sec-Fetch-Site / Origin matrix), with `OPEN_ELEMENT_DISABLE_CSRF=1` as
  the documented opt-out.
- `sanitizeHtml` / `isSafeUrl` allow-list sanitizer exported from
  `@openelement/element/sanitize`; head-injection sanitization tightened
  (`<base>`, `<meta http-equiv>`, raw `<script>` rejected); forced
  `noopener` on `target="_blank"` case variants.

**First mile and deployment**

- `deno task build && deno task start` is the one-command path; request-time
  builds emit `dist/server/index.js` (Nitro-mountable) plus a standalone
  `dist/server/serve.mjs` (`node dist/server/serve.mjs`, no CLI needed).
- Fail-closed static prerender: a failing dynamic route fails the build.
- Styled 404 pages; unmatched request-time paths render them with a real
  404 status and correct cache headers.
- Nitro presets `node-server` and `cloudflare_module` proven by CI gates.

**Islands and the element runtime**

- Hydration strategies `load` / `idle` / `visible` / `only`
  (`hydrate:`, see breaking changes); function-mode islands re-render on
  signal change; Preact islands via `@openelement/app/preact`.
- Keyed `<For each key>` reconciliation exported from the element root,
  with matched-hydration boundary markers.
- `ErrorBoundary` auto-captures subtree render failures on SSR and the
  client (ADR-0053 Layer 2).

**Content, routing and authoring**

- `.mdx` route files; i18n routing (`/zh/` prefixes, locale-aware links);
  sitemap + robots emission; the generated-data virtual module
  (`@openelement/generated/*`); SPA mode with a route manifest; all route
  matching on WHATWG URLPattern.
- Registration decoupling (#960, ADR-0128): definePage route modules
  register their page class under the route-path fallback tag, so the
  definePage render always runs — the silent self-registration bypass is
  gone, with a scanner warning for the residual tag-collision corner.

**Release engineering**

- AutoFlow3 two-stage publishes with durable prepare records; a 45-gate
  release tier (packed-starter e2e, cross-browser fixture gates, consumer
  smokes, third-party WC smoke); the public-interface snapshot now guards
  re-exported names mechanically (#592).

## Breaking changes since 0.41.x

1. **`IslandOptions.strategy` → `hydrate`** (ADR-0127): the old name is
   deleted with no alias. App-side `defineIslandConfig({ hydrate })` was
   already the spelling.
2. **Shape-1 SSR markup gains one wrapper element** (#960, ADR-0128):
   definePage routes with a self-registered content element now render the
   content element inside the fallback-tag page element. CSS/selectors
   targeting the old root tag must retarget. See the migration guide.
3. **Head-injection tightening** (#931): `<base>` / `<meta http-equiv>` /
   raw `<script>` in `headExtras` are stripped or rejected.
4. **Removed exports** (unfrozen alpha surface): `@openelement/app` dropped
   `i18nStaticPaths` / `switchLocale` / `AppIslandOptions` and the
   `OpenElementRouteNode` re-export from `./model`;
   `@openelement/ui/open-props-tokens` dropped `OPEN_PROPS_TOKEN_CSS`.
5. **Pure-static builds no longer emit `dist/server/`** (#953): the
   build-time SSR bundle is removed from the deployable tree.
6. **Minimum Deno version is 2.8** (CI pins 2.9.x). The generated
   `dist/server` requires Node 24+ today (a clean early error below that) — the documented
   Node 18+ claim was wrong; fixed in the 0.43 line by #969.

## Upgrade from 0.41.x

**Pure-static and SPA projects: zero source changes.** Bump the
`@openelement/*` specifiers to `0.42.0`, refresh the lockfile, rebuild.
Fresh byte-level proof (2026-08-15, against the exact stable code): the
same scaffolded static project built on 0.41.2 and on the 0.42 line
produces byte-identical pages and content artifacts; the only user-visible
markup difference is the documented #960 wrapper on shape-1 pages, and the
only tree-shape difference is the #953 `dist/server` removal.
Details and per-scenario recipes: `docs/release/v0.42.0-migration.md`.

## Frozen at 0.42.0 / explicitly not frozen

Frozen (ADR-0122 §1–§4): the loop contract (loader/action signatures,
fail/redirect algebra + HTTP encodings, PRG revalidation, no-JS baseline),
the action protocol (`x-openelement-action`, the morph client contract,
channel symmetry), the CSRF default, and first-mile start semantics.
Breaking changes to these require an amendment ADR.

Not frozen / not claimed (§5–§6): framework session/flash, cache/ISR
(`revalidate` stays inert forward-compat data), streaming SSR, performance
SLOs, the third-party WC SSR corpus (0.43), production runtime recovery
(0.44). Signed-in apps use the better-auth recipe.

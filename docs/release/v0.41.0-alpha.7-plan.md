# v0.41.0-alpha.7 Version Plan - Networked Desktop Dogfood

## Objective

Run a **read-only / accountless networked desktop dogfood app** against public
Mastodon/GoToSocial-compatible APIs to stress-test the openElement framework
surface that already exists in v0.41. Alpha.7 does not add new framework
primitives; it uses real network I/O and desktop runtime pressure to expose gaps
in SPA mode, Deno Desktop, third-party Web Components interop, render pipeline
performance, local state/cache, and error boundaries.

The design source of truth lives in
`docs/dogfood/mastodon-desktop/README.md`.

## Product Intent

This is a **framework dogfood**, not a social client product. Reader (alpha.5/6)
proved local-first documents, annotations, and desktop reading ergonomics.
Mastodon Desktop proves a different surface:

- Remote public API fetching with realistic failure modes.
- Timeline-style navigation with dynamic content.
- Cache, error, retry, and rate-limit states as normal UI flows.
- Third-party Web Components used inside a desktop shell.
- Long-running SPA behavior under continuous data updates.

The app stays deliberately narrow so the framework learning stays sharp.

## Dependencies

Alpha.7 starts only after the following alpha.6 outcomes exist:

- OpenElement App owns RouteGraph, RenderPipeline, and RequestContext.
- Hono/Vite/Nitro are official adapters/drivers over OpenElement concepts.
- Deno Desktop is defined as a first-party OpenElement app target.
- Reader has a regression smoke matrix that proves the desktop app substrate.
- The first-party stack contract is documented.

## Workstreams

### A. Third-party Web Components Interop Foundation

- Close #221: restore third-party WC event interaction smoke without fixed
  sleeps.
- Expand smoke matrix to cover Shoelace forms/dialogs and Lit/openElement
  nesting.
- Ensure third-party WCs can be used inside the desktop shell before the shell
  depends on them.

### B. Desktop App Shell

- Create a macOS-focused Deno Desktop app scaffold in
  `examples/deno-desktop-mastodon/`.
- Reuse the alpha.6 Deno Desktop target contract instead of creating
  app-specific host glue.
- Provide sidebar, content panel, detail panel, settings, and status/error
  surfaces using OpenElement UI, Open Props, and optionally Shoelace.
- Keep the app keyboard-friendly and desktop-native in feel.

### C. Public Mastodon/GoToSocial Client Boundary

- Add a small public API client boundary for Mastodon/GoToSocial-compatible
  instance APIs.
- Support instance selection without login.
- Fetch public timeline, profile, and status/thread data.
- Surface rate limits, network failures, invalid instance URLs, and retry states
  as normal UI flows.
- Keep all API assumptions documented with fixtures or contract tests.

### D. Read-Only Social Surfaces

- Public timeline route.
- Profile route.
- Status detail/thread route.
- Local saved accounts/statuses as bookmark-like state.
- Basic search where public instance APIs support it.
- Empty/loading/error states for every route.

### E. Local State And Cache

- Store selected instance, recent profiles, saved statuses, and lightweight
  response cache locally.
- Keep credential storage completely out of scope.
- Add deterministic fixtures so tests do not depend on live network every run.
- Allow one live-network smoke to run manually or behind an explicit opt-in flag.

### F. Toolchain Truth

- Pin `.dvmrc` to Deno `2.9.0` (stable). The full gate matrix, including
  `deno pack` / `pack:dry-run`, passes on stable.
- Align CI: `setup-deno-workspace` already reads `.dvmrc`; update the standalone
  JSR consumer monitor to read `.dvmrc` too.
- Record the decision in `docs/current/VERSION_PLAN.md`,
  `docs/release/v0.41.0-beta.1-plan.md`, and `.dvmrc`.
- Keep Deno 2.8+ as the public minimum; canary remains acceptable only for
  Deno Desktop preview features outside the main gate matrix.

### G. Beta.1 Adoption Freeze Handoff

- Create GitHub issues for beta.1 work: five-minute starter path, public API
  docs, website adoption experience, competitor positioning, release truth, Deno
  toolchain truth, logo/brand.
- Link the issues from `docs/release/v0.41.0-beta.1-plan.md`.

### H. Verification

- Browser smoke for route rendering and fixture-backed API flows.
- Deno Desktop smoke for shell boot, navigation, settings persistence, and
  native window behavior where supported.
- Contract tests for public API client parsing and error handling.
- Long-running stress test (30+ minutes) to check memory and stability.
- Screenshot smoke for the main desktop layout.

## Non-Goals

- No OAuth/session flow.
- No direct messages.
- No notifications.
- No streaming API or background sync.
- No compose, reply, favorite, boost, follow, or authenticated mutation.
- No encrypted credential storage.
- No official mobile shell.
- No server/data/forms/session/cache framework primitives.
- No claim that OpenElement has complete server/data/forms/session/cache
  primitives because of this dogfood app.

# v0.41.0-alpha.7 Version Plan - Mac Mastodon Desktop Incubation

## Objective

Start the OpenElement + Deno Desktop macOS Mastodon/IM incubation project after
alpha.6 validates the App/protocol architecture and first-party desktop target.

This project should not disappear, but it also should not drag OAuth,
notifications, direct messages, or authenticated mutations into alpha.5/alpha.6.
Alpha.7 is a narrow networked desktop dogfood line: prove that the framework can
support a polished macOS desktop social-reading app against public
Mastodon/GoToSocial-compatible APIs.

## Product Intent

The app is an incubation project, not an official social client product yet.
Its job is to stress a different part of OpenElement than Reader:

- Reader proves local-first documents, annotations, notes, export, source
  ingestion, and desktop reading ergonomics.
- Mac Mastodon Desktop proves remote public API fetching, cache/error states,
  rate-limit handling, timeline-style navigation, profile/status surfaces, and
  networked desktop UX.

The long-term idea can evolve toward an IM-like desktop client, but alpha.7
should stay read-only/accountless so the framework learning stays sharp.

## Dependencies

Alpha.7 starts only after the following alpha.6 outcomes exist:

- OpenElement App owns RouteGraph, RenderPipeline, and RequestContext.
- Hono/Vite/Nitro are official adapters/drivers over OpenElement concepts.
- Deno Desktop is defined as a first-party OpenElement app target.
- Reader has a regression smoke matrix that proves the desktop app substrate.
- The first-party stack contract is documented.

## Workstreams

### A. Desktop App Shell

- Create a macOS-focused Deno Desktop app scaffold.
- Reuse the alpha.6 Deno Desktop target contract instead of creating
  app-specific host glue.
- Provide sidebar, content panel, detail panel, settings, and status/error
  surfaces using OpenElement UI and Open Props.
- Keep the app keyboard-friendly and desktop-native in feel.

### B. Public Mastodon/GoToSocial Client Boundary

- Add a small public API client boundary for Mastodon/GoToSocial-compatible
  instance APIs.
- Support instance selection without login.
- Fetch public timeline, profile, and status/thread data.
- Surface rate limits, network failures, invalid instance URLs, and retry states
  as normal UI flows.
- Keep all API assumptions documented with fixtures or contract tests.

### C. Read-Only Social Surfaces

- Public timeline route.
- Profile route.
- Status detail/thread route.
- Local saved accounts/statuses as bookmark-like state.
- Basic search where public instance APIs support it.
- Empty/loading/error states for every route.

### D. Local State And Cache

- Store selected instance, recent profiles, saved statuses, and lightweight
  response cache locally.
- Keep credential storage completely out of scope.
- Add deterministic fixtures so tests do not depend on live network every run.
- Allow one live-network smoke to run manually or behind an explicit opt-in flag.

### E. Verification

- Browser smoke for route rendering and fixture-backed API flows.
- Deno Desktop smoke for shell boot, navigation, settings persistence, and
  native window behavior where supported.
- Contract tests for public API client parsing and error handling.
- Screenshot smoke for the main desktop layout.

## Acceptance

- [ ] The app boots as an OpenElement + Deno Desktop macOS incubation app.
- [ ] A user can choose a public Mastodon/GoToSocial-compatible instance without
      login.
- [ ] Public timeline, profile, and status detail routes work from deterministic
      fixtures.
- [ ] Public API failures and rate-limit states are visible and test-covered.
- [ ] Local saved statuses/accounts persist without credentials.
- [ ] Browser smoke and Deno Desktop smoke cover the core read-only workflow.
- [ ] Docs clearly state that alpha.7 is read-only/accountless incubation, not a
      production social client.

## Non-Goals

- No OAuth/session flow.
- No direct messages.
- No notifications.
- No streaming API or background sync.
- No compose, reply, favorite, boost, follow, or authenticated mutation.
- No encrypted credential storage.
- No official mobile shell.
- No claim that OpenElement has complete server/data/forms/session/cache
  primitives because of this incubation app.

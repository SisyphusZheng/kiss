# v0.41.0-alpha.13 Version Plan — Published-consumer and release reliability

> Base: `v0.41.0-alpha.12` (five npm packages published under the `alpha` tag).
> Alpha.12 release closure remains incomplete: its published starter failed the
> post-publish Deno typecheck because the Element JSX runtime subpath was not
> resolvable from npm.

## Objective

Make the five-package release train consumable from the registry and make
AutoFlow report registry propagation accurately. Alpha.13 is a release-quality
patch train: it adds no framework features and does not reinterpret alpha.12 as
a completed release.

## P0 release blockers

| Slice  | Issue                                                          | Outcome                                                                                                | Blocked by |
| ------ | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ | ---------- |
| A13.01 | [#439](https://github.com/open-element/openelement/issues/439) | Published Element JSX runtime and its typings resolve in an exact-version generated starter.           | none       |
| A13.02 | [#440](https://github.com/open-element/openelement/issues/440) | Publish verification retries boundedly through npm propagation delay and preserves useful diagnostics. | none       |

The two P0 slices can proceed in parallel. Both must land before the alpha.13
publish flow starts; #439 is the hard consumer-release blocker.

## P1 audit remediation

The pre-existing alpha.13 audit train remains in scope. These are independently
deliverable vertical slices, but none may weaken the P0 published-consumer
release gates.

| Slice  | Issue                                                          | Outcome                                                                                                    |
| ------ | -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |

[#435](https://github.com/open-element/openelement/issues/435) tracks 43

alpha.13, but do not turn it into unbounded release scope.

## Delivery order

1. #439: restore the published starter/JSX runtime contract.
2. #440 and #429: make post-publish and consumer verification dependable.
3. #432: make the generated starter follow the release version automatically.
4. #430, #431, #433, and #434: complete the bounded P1 audit slices in parallel.
5. #435: triage only; promote individual items only through a new scoped issue.

## Acceptance and release evidence

- [ ] #439 and #440 are closed with packaged and published-consumer evidence.
- [ ] A clean Deno workspace can generate and typecheck a starter pinned to the
      exact published alpha.13 packages.
- [ ] All five npm packages exist at exactly `0.41.0-alpha.13` and each `alpha`
      dist-tag points to that version.
- [ ] Post-publish Deno, Node ESM, starter, Nitro, third-party WC, jsDelivr,
      Git tag, GitHub prerelease, and source/documentation version evidence agree.
- [ ] Any npm propagation retry emits its attempts and final observed registry
      state; it must not hide a persistent package error.

## Non-goals

- No stable `0.41.0` declaration.
- No republishing or rewriting immutable alpha.12 npm artifacts.
- No medium- or low-severity audit scope expansion solely to finish this patch.

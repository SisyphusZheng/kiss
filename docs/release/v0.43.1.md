# v0.43.1

**Cumulative maintenance baseline for the frozen 0.43 line.** This release is
based on the actual `v0.43.0...v0.43.1` repository delta, not only PR #1115:
the pre-release implementation was 16 commits and 659 files ahead of the
`v0.43.0` tag before release-note and version-bump commits. It requalifies 33
earlier fixes, closes six additional post-merge findings, and independently
rechecks the framework and the Supabase × Cloudflare reference SaaS.

## What changed from v0.43.0

### Framework correctness and public surface

- Nested function components and `<For>` callbacks now retain request-scoped
  loader/action data through complete SSR evaluation, including concurrent
  render isolation and error cleanup.
- SSR, hydration, and CSR share stricter signal, attribute, error-recovery, and
  third-party-element rules. Signal-valued props receive automatic hydration
  markers; unsupported event half-hydration fails loudly instead of appearing
  to work.
- Fragment navigation can resolve ids through nested shadow roots, including
  direct loads, clicks, history traversal, and malformed percent-encoding.
- Vite development now invalidates edited SSR dependencies and serializes
  descriptor rescans so burst edits reload the final route/island graph.
- `ServerRouteContext<Env, Platform, Route>` and `ServerRouteMetadata` expose
  the actual generated server context without forcing Cloudflare object
  bindings into a string-only environment shape.
- Generic Markdown content collections land in
  `@openelement/adapter-vite`: `openElement({ content: { collections } })`,
  `createCollectionPlugin`, generated typed data modules, declarative
  frontmatter validation, and the same sanitizer used by framework content.
  The existing blog path remains compatible as a thin collection alias.
- Public package entries no longer name `internal/` modules. Five
  adapter-owned build/content types move from `@openelement/element` to
  `@openelement/adapter-vite`; their shapes are unchanged.

### Supabase × Cloudflare reference SaaS hardening

- Ten forward-only migrations advance the starter from 13 to 23 migrations.
  They add explicit least-privilege table/sequence/function ACLs, workspace
  RLS qualification, FK/RLS indexes, bounded Notes constraints, and a corrected
  Stripe reconciliation predicate.
- Notes use stable composite keyset pagination, a 10-row render cap, title/body
  database constraints, and a 2 MiB SSR response budget verified with 10,001
  rows on generated Node and Workers artifacts.
- Admin payment/scan replay now performs authorization, state transition, and
  actor audit in one transaction; current `auth.users.raw_app_meta_data` is
  checked so a stale admin JWT cannot authorize replay after demotion.
- Attachment deletion records durable intent before Storage mutation and
  converges through an idempotent reconciler after Storage failure, database
  failure, interruption, or duplicate calls.
- Realtime remains an invalidation channel: subscribe/reconnect performs
  bounded durable reconciliation, retains the JWT only in private element
  memory, and removes the one-time token from the DOM after handoff.
- Checkout retries use a stable request body for a persisted idempotency key;
  anonymous RPC execution and cross-user order reads are proven closed.
- Scanner orchestration owns its timeout even when a provider ignores
  `AbortSignal`. A missing real scanner remains explicit and fail-closed; this
  release does not claim real clean/EICAR provider qualification.
- `reject_audit_mutation()` now has an empty pinned `search_path`. Post-apply
  Supabase Advisor reports no mutable-search-path finding.

### Architecture, security, and release discipline

- One allow-list sanitizer now covers element HTML, adapter content, and the
  documentation site; duplicated sanitizer dependencies and policies are gone.
- Architecture, package graph, public-interface, type-safety, release-truth,
  migration immutability, and provider-evidence gates reject the drift found by
  the audit.
- ADR-0140 places the project in 0.43.x maintenance mode after this release:
  compatible bug/security/runtime/documentation fixes continue as patches, but
  no 0.44 feature train is scheduled. A future minor requires a maintainer ADR
  backed by a concrete cross-application need. CRM domain features and
  China-market integrations remain outside framework packages.

## Compatibility and upgrade notes

1. Bump all five `@openelement/*` packages together to `0.43.1` and refresh
   the lockfile. The Node 24+ generated-server floor is unchanged.
2. If importing any of these build-only types from `@openelement/element`,
   change the import authority to `@openelement/adapter-vite`:
   `OpenElementBlogOptions`, `OpenElementBuildContextLike`,
   `OpenElementHeaderNavLink`, `OpenElementI18nContextOptions`, and
   `OpenElementNavSection`. Runtime behavior and type shapes do not change.
3. Supabase starter deployments must review and apply the ten new ordered
   migrations. Do not edit or squash the 13 migrations shipped with v0.43.0.
   Back up production data, run the repository migration workflow in `check`
   mode, then explicitly authorize `apply`.
4. The hosted qualification project retains 13 reviewed
   authenticated-callable `SECURITY DEFINER` RPC warnings and the project-level
   leaked-password-protection warning. They are documented residual/configuration
   items, not new anonymous ACL or RLS exposure. Production password deployments
   should enable leaked-password protection when their Supabase plan supports it.
5. No framework ORM, session, cache, generic outbox/recovery, scanner engine,
   CRM model, or China-specific integration is added by this patch.

# v0.41.0-alpha.6 Version Plan - App Protocol Architecture Hardening

## Objective

Turn the alpha.5 Reader and architecture audit lessons into a cleaner
OpenElement framework architecture. Alpha.6 should make OpenElement's two core
products explicit:

- **Web Components fullstack framework**: app model, routing, rendering,
  islands, assets, deployment, and desktop targets.
- **Web Components Basic Element**: the small authoring layer behind
  `OpenElement`, SSR-safe lifecycle, render hooks, and custom-element ergonomics.

Vite, Hono, Nitro, Deno Desktop, Preact islands, third-party Web Components, and
Open Props are official first-party stack choices. The alpha.6 work is to make
those choices enter through OpenElement-owned contracts instead of leaking as
package identity.

## Product Stance

```text
OpenElement App owns: RouteGraph, RenderPipeline, RequestContext,
AssetManifest, IslandManifest, DeploymentTarget.

Official adapters implement: Vite build/dev, Hono request driver,
Nitro deploy output, Deno Desktop app target.

Reader proves: the framework survives a beautiful, stateful, local-first desktop
application.
```

OpenElement should not become "HonoX with Web Components." Hono remains the
default request/server driver, but `@openelement/app` owns the application
model. Vite remains the default build adapter, Nitro remains the default deploy
adapter, and Deno Desktop remains the preferred desktop dogfood target.

## Workstreams

### 0. Product Truth And ADR Closure

- Adopt ADR-0110 as the current public product doctrine:
  `Web Components Fullstack Framework + Basic Element`.
- Adopt ADR-0111 as the App ownership boundary before A6.2/A6.7 implementation.
- Sync README, STATUS, ROADMAP, VERSION_PLAN, PACKAGE_SURFACE, website-facing
  docs, and release plans so they agree on product formula, package graph, and
  active version line.
- Add a `docs:truth` gate so future releases catch product/version/package drift.

### A. Package And Protocol Separation

- Split package responsibilities so protocol-level contracts can be tested
  without booting the full default stack.
- Keep runtime-free/browser-facing packages free of ambient host assumptions.
- Keep Basic Element small and SSR-safe.
- Keep official adapters thin and explicit.

### B. App Model Ownership

- Define an OpenElement RouteGraph that is independent from Hono.
- Define an OpenElement RequestContext that is mapped from Hono in the Hono
  adapter.
- Define a RenderPipeline that covers page render, layouts, head/assets,
  islands, error handling, and output serialization.
- Ensure app model tests run without the Hono adapter, then add Hono adapter
  coverage separately.

### C. Official Stack Contracts

- Vite: official dev/build and asset manifest adapter.
- Hono: official request/server driver.
- Nitro: official deployment output adapter.
- Deno Desktop: official desktop app target.
- Open Props: token foundation for OpenElement UI and Reader.
- Preact: optional island authoring adapter, not the default OpenElement UI
  model.
- Third-party WC libraries: first-class compatibility target, not a replacement
  for Basic Element conveniences.

### D. Reader Regression Dogfood

- Promote Reader from "working proof" to regression-grade app.
- Keep Reader local-first and legally independent from WeRead.
- Use real public-domain/open fixtures where possible.
- Exercise source ingestion, PDF/text reading, search, annotations, note jumps,
  export, settings, Deno Desktop behavior, OpenElement UI, Preact islands, and
  third-party WC compatibility.

### E. Security And Static Analysis Closure

- Treat open CodeQL alerts as alpha.6 release hygiene, not a separate cleanup
  train.
- Close the currently open code-scanning backlog through focused, agent-ready
  issues: #186, #187, #188, #189, #190, and #191.
- Prefer structural fixes over suppressions: validated URL/specifier builders,
  parser-backed HTML/tag extraction, structured code-generation literals, and
  simpler async watcher state.
- Keep these fixes inside A6.6 unless a change exposes a deeper app/protocol
  contract issue that belongs in A6.1 through A6.5.

## Execution Order

1. Complete alpha.5 closure and release-note truth first.
2. Land A6.0 and A6.0b before broad implementation so public product language
   and App ownership are settled in ADR-0110 and ADR-0111.
3. Land A6.8 early so architecture work has one shared vocabulary and stack
   contract.
4. Land A6.1, A6.2, and A6.3 as adapter/package separation work. These can run
   in parallel if they do not rewrite the same public exports.
5. Land A6.4 before widening Reader or manifest expectations around third-party
   Web Components.
6. Land A6.5 after A6.4 clarifies what hydration supports for Basic Element and
   non-OpenElement custom elements.
7. Land A6.7 once SSG/app/page contracts are explicit; this is the central
   architectural slice.
8. Land A6.9 after the alpha.5 Reader verification workflow exists.
9. Land A6.10 last as the end-to-end dogfood proof.
10. Land A6.6/A6.6a opportunistically after alpha.5 release, using evidence from the
    completed alpha.5 and alpha.6 test runs. Include the CodeQL cleanup issues
    #186 through #191 in this slice so security/static-analysis noise is closed
    before alpha.6 release review.

## Acceptance

- [ ] Public docs describe the two primary products: Web Components fullstack
      framework and Web Components Basic Element.
- [ ] ADR-0110 and ADR-0111 are accepted and indexed.
- [ ] README, STATUS, ROADMAP, VERSION_PLAN, PACKAGE_SURFACE, and release plans
      agree on product formula, active version line, and current package graph.
- [ ] Vite, Hono, Nitro, Deno Desktop, Open Props, Preact islands, and
      third-party WC libraries have explicit first-party roles.
- [ ] `@openelement/app` owns route graph, request context, and render pipeline
      concepts; Hono is an adapter/driver over those concepts.
- [ ] Nitro is an explicit deploy adapter or subpath, not an accidental
      adapter-vite public surface leak.
- [ ] SSG exposes OpenElement render-engine concepts before Hono/Vite-specific
      details.
- [ ] Content core can exist without importing Vite types.
- [ ] Manifest/hydration contracts distinguish Basic Element conveniences from
      generic third-party WC compatibility.
- [ ] Deno Desktop is documented and tested as a first-party app target, not as
      a localhost browser preview.
- [ ] Reader has a regression smoke matrix that exercises the real framework
      stack.
- [ ] The alpha.6 CodeQL cleanup backlog is closed: #186, #187, #188, #189,
      #190, and #191.
- [ ] The alpha.6 product-truth backlog is closed: #192, #193, and #194.

## Non-Goals

- No Mastodon/GoToSocial app in alpha.6.
- Mac Mastodon Desktop incubation is reserved for alpha.7 after the App,
  protocol, and Deno Desktop target contracts are clean.
- No new server/data/forms/session/cache product surface unless required to
  express the app/protocol contracts above.
- No React/Vue/Svelte adapter expansion beyond the existing optional Preact
  island path.
- No generic desktop abstraction over Tauri/Electron/Capacitor.
- No replacement of Vite/Hono/Nitro as the official defaults.
- No private WeRead API integration or copyrighted book fixtures in Reader.

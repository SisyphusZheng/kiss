# v0.42.0-alpha.16 Remediation Plan & SOP

Status: DRAFT (2026-08-10) · Supersedes nothing · Inputs: round-3 audit (#915–#936), client interaction matrix (#937–#943), starter fixes already on main (621bc1d2, e45cdf9f, b4e06079, 3a8f92c1, 43c22a51, a5371727)

## 0. Diagnosis — why "everything" broke at once

The 28 alpha.16 issues are not 28 independent defects. They trace to one systemic gap:

> **The monorepo fixtures were green while the published starter was broken.**
> Every headline feature was verified against `__fixtures__` code that is _not_ the code `@openelement/create` ships. The starter had no generated-artifact verification at all until the round-3 e2e.

Consequences observed in the wild (published alpha.15, user-side only):

- Enhanced form loop: fixture `/form` passes e2e; starter `/contact` never morphs (#937).
- Progressive enhancement: fixture no-JS path passes; starter native POST → 403 (#938).
- Starter island: dead on click for the entire alpha.15 lifetime (function-mode pattern, #940; template hotfixed 621bc1d2).
- Starter visuals: unstyled CSS, clipped logo, jammed nav — all invisible to markup-level checks.

Therefore the plan's spine is: **fix the verification gap first, then fix bugs in an order the gate can protect.**

## 2. SOP — every fix, no exceptions

1. **Reproduce at the level the bug was found.** Browser-found bug → browser repro (Playwright). Starter-found bug → repro against a project generated from the _packed_ artifact, not the monorepo fixture. No repro, no fix.
2. **Root cause in one sentence before editing.** Write it in the commit message. If you cannot state it, you are treating a symptom.
3. **Minimal change, surrounding conventions.** No opportunistic refactors; cross-runtime constraints stay (adapter-vite/create: Web/ES APIs + `node:` + `npm:` only).
4. **Regression test at the repro level**, plus unit level when the logic is unit-testable. A fix without a same-level test is incomplete by definition.
5. **Verification ladder, all rungs:** `deno fmt` + `deno lint` (changed files) → package tests → packed-starter generation (`check`/`build`) → browser smoke for anything UI-visible → `deno task arch:check` before commit → full `deno task test` before push.
6. **One finding = one conventional commit** straight to main. No tags, no publish, no autoflow release commands outside the release run.
7. **Close the loop:** issue closed with the commit SHA; behavior changes get a changelog line (#931); docs/comments that described the old behavior are updated in the same commit.
8. **User-side re-verification for Wave 1 items:** after each Wave 1 fix lands, re-run the corresponding scenario in the persistent blog e2e project (rebuilt from a fresh pack) — the same surface where the bug was found.

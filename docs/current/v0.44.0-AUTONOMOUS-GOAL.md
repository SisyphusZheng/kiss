# Goal: complete v0.44 Alpha integration and semantic convergence

Finish the v0.44 framework architecture by integrating the parallel Alpha workspaces
at Alpha.8, then completing internal Alpha.9 semantic convergence in the same
worktree, branch and PR. Do not activate the three-role release loop during Alpha.

## Objective

1. Require #1193 closure evidence for minimum history safety, the frozen collaboration
   contract, executable path ownership and one exact common base SHA.
2. Create alpha.1 through alpha.7 as independent workspaces from that SHA.
3. Give one agent end-to-end ownership of each workspace's code, tests, commits and
   branch.
4. Run the seven workspaces concurrently with targeted RED/GREEN gates.
5. Use alpha.8 as the sole integration workspace and agent.
6. Record the Alpha.8 checkpoint in PR #1199.
7. Complete ADR-0150 semantic convergence and current ownership evidence as Alpha.9.
8. Pass authoritative full CI for the exact final PR #1199 head and merge that SHA to
   `dev` before explicitly unblocking Beta.1.

## Alpha execution rule

Alpha numbers are internal work identifiers, not published versions. Alpha has no
thinker/implementer separation, no release verifier, no unanimous release GO, and no
per-workspace release ceremony. A workspace agent implements and verifies its owned
slice directly. The alpha.8 agent performs final aggregation and integration repair.

Do not tag, publish, update a dist-tag, create a GitHub Release, promote `main`, delete
branches, or claim a public Alpha release.

## Workspace safety

- Separate worktree and branch per workspace; never two writers in one checkout.
- Enforce `tools/config/v044-alpha-workspaces.json` as the write boundary.
- Shared contract changes require an explicit cross-workspace update before code
  proceeds.
- No fallback architecture, hidden compatibility, weakened tests, workspace aliases,
  private cross-package imports or unsupported claims.
- Workspace agents run focused tests and the fast push tier, not the full matrix.
- Alpha.8 consumes exact source SHAs, records their linear integrated-SHA mapping and
  owns the only full-CI integration PR.

## Alpha.9 admission work

ADR-0150 makes Alpha.9 a hard Beta.1 admission blocker. PR #1199 remains the single
implementation and qualification authority for Alpha.8 and Alpha.9. One canonical
semantic owner and mechanical parity evidence are required for every admission-critical
concept; no compatibility bridge, hidden fallback or second semantic authority may be
introduced.

## Deferred work

ADR-0149 owns the post-Alpha sequence. Framework publication and branch convergence
begin at Beta.1; #1156 and #1187 move to Beta.2; #1150 moves to Beta.3; #1157 #1158
#1159 and #1177 move to Beta.4; #1188 and #1189 close under #1192 in Beta.5 with
independent SaaS qualification. None blocks Alpha.8 integration.

## Completion

This Goal completes when Alpha.8 and Alpha.9 are accepted in PR #1199, its exact green
head SHA is merged unchanged to `dev`, all Alpha issues have exact closure evidence,
and Beta.1 is explicitly unblocked. The three-role release loop starts only in the
Beta Goal; Alpha.8 and Alpha.9 remain unpublished.

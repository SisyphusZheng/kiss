# v0.44 Alpha/Beta Autonomous Execution Goal

## Transferable objective

Advance OpenElement from the current `v0.44.0-alpha.0` planning baseline through every
mandatory alpha and beta work package, producing an exact-SHA RC admission decision,
while preserving ADR-0143's single compiled Element model and ADR-0146's three-role
execution separation.

The execution configuration is fixed:

```text
Thinker/orchestrator: configured thinker model, reasoning effort low
Implementation:       configured executor model, default effort high
Version verification: fresh configured executor session, default effort high
```

Exact model, provider, CLI and role-profile identity lives in executable configuration
(`tools/config/v044-roles.json`), never in documentation. Roles are invoked through the
repository role runner (`deno task v044:role`).

## Completion condition

This Goal is complete only when all of the following are true:

- every mandatory issue from alpha.0 through beta.2 is closed with repository and
  GitHub evidence;
- every published alpha and beta candidate has a fresh-session, test-driven release
  verifier PASS plus an independent deterministic harness PASS;
- #1181 records final-alpha GO, #1150 records beta.1 UI/Zag qualification and #1177
  records beta.2 website qualification;
- #1178 contains an exact-SHA RC GO/NO-GO packet;
- the execution state is `AWAITING_HUMAN_GO` for RC promotion or `COMPLETE` after the
  human-approved RC promotion steps finish;
- no runtime VNode/binding fallback, unapproved public package, hidden workspace alias,
  waived gate or unrecorded architecture change remains.

RC SaaS qualification (#1179) and Stable promotion (#1180) are explicitly outside this
Goal. They begin only after a human approves the RC candidate and creates the next Goal.

## Autonomy envelope

Within one approved bootstrap run, the thinker may:

- read repository, Git and GitHub state;
- create bounded dispatch packets;
- invoke the configured implementer and a fresh release verifier through `deno task
  v044:role`;
- edit in-scope repository files through the executor;
- run non-destructive tests, builds, browser checks and artifact inspection;
- create local commits, push a scoped feature branch, open/update PRs and update issue
  evidence when the bootstrap prompt grants those actions;
- continue through repair loops without asking for routine implementation decisions.

The active bootstrap authorizes the complete `alpha.1` through `beta.2` prerelease
release flow — `dev`→`main` integration, tag, npm publish, dist-tag change, GitHub
Release, evidence/issue updates and cursor advancement — after a unanimous
implementer/release-verifier/thinker GO against the exact candidate SHA with all gates
green. `alpha.0` remains strictly unpublished.

It must stop for human input before:

- changing accepted architecture, public package topology, release doctrine or Goal;
- destructive cleanup whose exact target is not already authorized;
- RC admission (#1178) or any Stable promotion step;
- accepting a security exception or waiving a deterministic gate.

## Blocked condition

The Goal becomes blocked only when a required capability or decision cannot be obtained
after the retry policy in the SOP is exhausted. Examples include an unavailable
configured executor, missing credentials, repeated non-deterministic infrastructure failure, contradictory
accepted ADRs, or a required architecture choice. Ordinary failing tests are repair work,
not a blocker.

## Goal text

When the new task supports persistent Goals, create it with this exact objective:

> Drive OpenElement v0.44 from alpha.0 through beta.2 using the repository-owned
> three-role loop: a low-effort thinker, a high-effort implementer, and a fresh
> high-effort test-driven release verifier at every version closure. Complete all
> mandatory issues and evidence, executing the authorized alpha.1–beta.2 release flow
> after each unanimous loop GO, then stop at the exact-SHA RC human GO gate (#1178).
> Do not change architecture, accept security exceptions or promote an RC/Stable
> without explicit human approval.

# v0.44 Alpha collaboration contract

This document freezes the minimum cross-workspace seams needed to run
alpha.1-alpha.7 concurrently and the non-negotiable integration boundary carried
through Alpha.8 and Alpha.9. It records existing ADR-0143 decisions, the #1160
vertical proof, and the final internal Part Program v1 convergence owned by ADR-0150
and #1208. It does not publish Alpha.9 or create a second public authoring API.

## Authoritative seed

The common seed is the behavior already proved by these paths:

- `packages/adapter-vite/src/internal/compiler/semantic-core/program.ts`
- `packages/adapter-vite/src/internal/compiler/semantic-core/compile.ts`
- `packages/adapter-vite/__fixtures__/compiled-element-v1/expected-program.json`
- `packages/element/src/internal/compiled/program.ts`
- `packages/element/src/internal/compiled/runtime.ts`
- `packages/adapter-vite/__tests__/compiled-element-v1.test.ts`
- `packages/element/__tests__/part-program-v1-conformance.test.ts`

The fixture is the cross-package exchange artifact. Workspaces must not create a
private cross-package TypeScript import to share compiler or runtime internals.

## Frozen semantic seams

1. One deterministic, serializable and versioned Part Program carries static
   structure plus typed fixed-Part and Region instructions.
2. Compiler output, not runtime discovery, owns dynamic-location identity.
3. Server serialization, fresh DOM creation and existing-DOM claim consume the same
   program semantics.
4. Fixed Parts own exact DOM sinks. Regions own bounded dynamic ranges, nested
   lifetime and structural identity.
5. A dependency invalidates only its compiled Part or Region. One element instance
   owns its subscriptions, listeners, ranges and cleanup.
6. Successful claim preserves matching node identity and live platform state.
   Mismatch handling is structured and bounded to the owning element or Region.
7. Unsupported syntax, instruction kinds and unsafe claim shapes fail closed. There
   is no VNode, binding-discovery, generic-hydration or interpreter fallback.
8. App and Island code consume generated element/activation artifacts. They never
   import Part, Region, Signal-engine or claim implementation details.

Alpha.1 extended the #1160 seed while preserving these semantics and emitted
deterministic fixtures. Alpha.8 reconciled those fixtures with the Element executors;
Alpha.9 closed the accepted wire grammar exactly and normalizes it to an immutable
Element-private `RuntimeProgramIR`. Future grammar changes require a new version and
coordinated compiler/runtime conformance evidence, not a runtime-only extension.

## Path ownership

The executable ownership map is
`tools/config/v044-alpha-workspaces.json`. Alpha.1-alpha.7 may write only their listed
paths. All other repository paths are read-only unless the main Alpha agent records a
genuine architecture/public-API/security decision and obtains human approval.

Cross-workspace defects are returned as a bounded handoff naming the owning workspace,
source SHA, failing fixture and expected behavior. A workspace does not repair another
workspace's files and does not add a compatibility bridge.

## Linear integration

All workspace branches start from the exact common SHA recorded in #1193. Because
`dev` requires linear history, alpha.8 records each accepted source head, cherry-picks
its reviewed commit series in dependency order, and records a source-to-integrated SHA
mapping. A conflict or behavior failure creates a new alpha.8 candidate; it never
rewrites a source branch or relabels old evidence.

Only PR #1199 opens the authoritative full-CI path to `dev`. Alpha.8 records the
integration checkpoint. ADR-0150 Alpha.9 then converges semantic ownership in the same
worktree, branch and PR. Only the final exact PR head may merge. Both checkpoints are
internal and unpublished; Beta.1 remains the first public v0.44 prerelease.

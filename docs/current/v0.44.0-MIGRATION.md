# v0.44 migration guide

v0.44 is an internal Alpha breaking change. It replaces the v0.43 runtime
renderer with compiler-generated, serializable Part Programs. The same program
semantics are used for server serialization, fresh DOM creation, and existing
DOM claim. There is no compatibility renderer, binding-discovery path, generic
hydration fallback, or interpreter fallback.

This guide documents the Alpha.5 migration toolchain. The frozen semantics are
defined by `docs/current/v0.44.0-ALPHA-CONTRACT.md`; this guide does not change
that contract.

## API changes

| v0.43 authoring                      | v0.44 authoring                                     |
| ------------------------------------ | --------------------------------------------------- |
| `defineElement(tag, definition)`     | `@element('tag') class Name extends OpenElement`    |
| `defineCustomElement(tag, Name)`     | `@element('tag')` on `Name`                         |
| `customElements.define(tag, Name)`   | `@element('tag')` on `Name`                         |
| VNode-returning render output        | compiler-lowered Part Program output                |
| binding descriptors and marker walks | compiler-owned Fixed Parts and Regions              |
| generic hydration helpers            | generated claim artifact consuming the same program |

Application and island code consumes generated artifacts. It must not import
Part, Region, Signal-engine, claim, or other private runtime implementation
modules.

## Application authoring (pages, islands, Preact)

The `@openelement/app` authoring surface converges on the compiled facade in
v0.44 (ADR-0143):

| v0.43 application authoring                              | v0.44 application authoring                                             |
| -------------------------------------------------------- | ----------------------------------------------------------------------- |
| `definePage({ head, renderIntent, render, error })`      | `definePage(CompiledPageClass, { head, renderIntent, props?, error? })` |
| `defineElement` / `defineIsland` re-exported from app    | removed — elements are compiled classes (`@element`)                    |
| render-scope `useLoaderData()` / `useActionData()` hooks | the descriptor's `props`/`error` projectors (pure context → props)      |
| route modules self-register (`customElements.define`)    | generated entries register every admitted route/island class            |
| `definePreactIsland` class extends `OpenElement` (DSD)   | plain autonomous custom element, light-DOM host content                 |
| `.mdx` routes execute runtime JSX through the MDX plugin | `.mdx` lowers to a compiled static page program at build                |

The canonical route module is a thin wrapper around the compiled page element
(the class lives in a non-route module, e.g. `app/components/`):

```tsx
// app/components/page-form.tsx — compiled by the open:compiled-element transform
import { element, OpenElement, property } from '@openelement/element';

@element('form-page', { root: 'shadow-open' })
export default class FormPage extends OpenElement {
  @property({ reflect: false, attribute: false })
  message = '';

  @property({ reflect: false, attribute: false })
  hasError = 0;

  render() {
    return (
      <main>
        <form method='post' data-open-enhance>
          <input id='message' name='message' type='text' value={this.message} />
          <button type='submit'>Send</button>
        </form>
        {this.hasError > 0 ? <p id='error'>message is required</p> : <span></span>}
      </main>
    );
  }
}
```

```ts
// app/routes/form.tsx — the route module the scanner discovers
import { definePage, fail, redirect } from '@openelement/app';
import FormPage from '../components/page-form.tsx';

export function action({ formData }: { formData: FormData }) {
  const message = String(formData.get('message') ?? '').trim();
  if (!message) return fail(422, { error: 'message is required', message });
  throw redirect(`/form?echoed=${encodeURIComponent(message)}`);
}

export default definePage(FormPage, {
  renderIntent: { mode: 'dynamic' },
  head: { title: 'Form' },
  // The single deterministic seam mapping request scope onto compiled props.
  props({ request, actionData }) {
    const echoed = request ? new URL(request.url).searchParams.get('echoed') : undefined;
    return {
      message: (actionData as { message?: string } | undefined)?.message ?? '',
      hasError: (actionData as { error?: string } | undefined)?.error ? 1 : 0,
    };
  },
  // Optional: renders the page's error variant (static Region branches) with
  // status 500 when a loader/action throws — the ADR-0121 §7 channel.
  error(error) {
    return { hasError: 0, message: '' };
  },
});
```

`loader`, `action`, `actions`, and `getStaticPaths` remain module named
exports. `renderIntent`/`head`/`route` metadata is unchanged. Pages whose
loader data is a flat record can omit `props` — the default projection maps
route params plus loader-data record entries onto the compiled properties.

Islands are single-module compiled classes; the delivery policy stays in the
statically scanned `defineIslandConfig` export:

```tsx
import { element, OpenElement, property } from '@openelement/element';
import { defineIslandConfig } from '@openelement/app';

export const openElement = defineIslandConfig({ hydrate: 'visible', ssr: true, dsd: true });

@element('live-counter', { root: 'shadow-open' })
export default class LiveCounter extends OpenElement {
  @property({ reflect: false, attribute: false })
  count = 0;

  increment(): void {
    this.count++;
  }

  render() {
    return <button type='button' onClick={this.increment}>{this.count}</button>;
  }
}
```

Page markup nests islands as custom-element hosts (`<live-counter
machine-id='a'></live-counter>`); the generated server entry expands admitted
island hosts recursively through their compiled classes per render (fail
closed on an unknown or unregistered OpenElement host; client-only and
foreign tags pass through per the admission plan). Host attributes must be
compiled `@property` fields of the island. Generated client entries install
`ensurePreHydrationClickCapture()` before any element module import, so
pre-upgrade interactions replay inside the claiming island's root.

Preact islands (`definePreactIsland`) no longer extend OpenElement and never
render into DSD: the island is an autonomous custom element whose light-DOM
host content is prerendered with preact-render-to-string via the class static
`renderSsr(props?)` when `ssr: true`; the client hydrates that content with
`preactHydrate` (or renders with `preactRender`) in `connectedCallback`, and
`disconnectedCallback` unmounts through the Preact owner (deferred, so a
same-turn DOM move keeps the tree). Props come from `options.props` plus host
attributes — the `getSsrProps`/`data-ssr-props` channel is removed. An
imperative `update()` re-renders through the existing Preact owner.

MDX/static content: a `.mdx` route resolves to a virtual module carrying a
compiled `@element` page class whose `render()` holds the markup as a fully
static template — the build lowers Markdown through the static subset
(headings, paragraphs, emphasis, links, images, lists, code, blockquotes).
Raw HTML blocks, JSX expressions, and ESM statements inside `.mdx` fail the
build closed with a source-located error; move interactive content into
compiled elements composed by the page.

Known v1 grammar boundaries (fail closed, by design): no slots or host
children, no per-item attribute slots in list Regions (list rows cannot emit
id attributes — id-keyed morph identity across list reorder needs a future
Region schema slot; positional morph alignment still applies), conditional
Region branches are fully static, and raw-text `<style>`/`<script>` elements
are rejected from templates (styles ship via `static styles` — the compiled
style scope uses adoptedStyleSheets on shadow roots and a document-head sink
on light roots).

## Deterministic codemod

Run the codemod without `--write` first so that the proposed source is visible:

```sh
deno run --allow-read --allow-env tools/migration/v044/migrate.ts path/to/component.tsx
```

Apply only a clean result after review:

```sh
deno run --allow-read --allow-write --allow-env tools/migration/v044/migrate.ts --write path/to/component.tsx
```

The codemod is pure until `--write` is supplied. A manual-repair diagnostic
leaves the source byte-for-byte unchanged and exits non-zero. Running it again
on migrated source is a no-op; this makes retries and CI rehearsals
idempotent.

The automatic subset is deliberately narrow:

- a top-level standalone `defineCustomElement(tag, Class)` or
  `customElements.define(tag, Class)` call;
- a string-literal tag, or a `const` string binding used as the tag;
- a class that directly extends `OpenElement` for registration conversion;
- a direct named `const` initializer for `defineElement`; and
- an object definition containing only `styles` and a zero-argument `render`,
  or a zero-argument render function.

The generated class uses the canonical `element` decorator and `OpenElement`
import. If the source does not already import the decorator, the codemod adds
`element` to the canonical named import from `@openelement/element` (#1209:
the compiler admits intrinsics by binding provenance, never by spelling). The
binding is compile-time-only — the compiler erases the decorator application
and strips the binding from generated imports; evaluated without the compiler
it is an inert no-op, not runtime registration machinery. Existing class
method bodies are retained as source text; the compiler remains responsible
for lowering supported render syntax to the Part Program.

## Manual repair cases

The codemod fails closed with a source location when semantics cannot be
proven. In particular, repair these cases by hand and rerun the tool:

- dynamic or invalid custom-element tags (`OE-MIGRATE-001`);
- registration hidden inside a conditional, callback, or other expression;
- an indirect class value, a class without a direct `OpenElement` base, or a
  namespace/default legacy import (`OE-MIGRATE-002`);
- `defineElement` render functions with parameters, `this`, async behavior,
  generator behavior, spreads, or additional definition properties;
- property declarations and external state that need `@property` fields or
  compiler-supported signal inputs; and
- unsupported JSX or JavaScript syntax rejected by the v0.44 compiler.

Do not replace a diagnostic by importing a private runtime helper. Convert the
authoring source to the supported decorator/property form or keep the case in
the manual migration queue until the compiler has an explicit instruction for
it.

## Legacy absence gate

After building the distributed artifacts, run the absence checker over every
artifact root:

```sh
deno run --allow-read --allow-env tools/check-v044-legacy-absence.ts \
  packages/element/dist \
  packages/adapter-vite/dist \
  packages/app/dist \
  packages/ui/dist \
  www/dist
```

The checker rejects legacy VNode, binding, activation, registration, and
generic-hydration symbols; legacy renderer module paths; legacy renderer
dependencies in code and metadata; marker-based hydration data; and private
Part/Region/Signal/claim imports in consumer artifacts. Missing roots or zero
artifact files fail closed instead of producing a false pass. Comments and
ordinary explanatory strings in code are not treated as runtime symbols, but
artifact metadata is scanned as data.

## 0.43 application rehearsal

For a real application, keep the rehearsal outside this repository worktree:

1. Copy the 0.43 application and record its source revision.
2. Run the codemod in preview mode and review every changed file and
   `OE-MIGRATE-*` diagnostic.
3. Apply clean conversions, manually convert property/state and unsupported
   render cases, and remove direct legacy helper imports.
4. Build with the v0.44 compiler and generated activation artifacts.
5. Run the absence gate over the packed or deployed artifacts.
6. Exercise fresh creation and existing-DOM claim in a browser, checking node
   identity, focus, form values, event listeners, and nested element lifetime.
7. Repeat the codemod and confirm the second run is byte-identical.

The Alpha.5 fixture rehearsal is executable with:

```sh
deno test --allow-read --allow-env tools/migration/v044/migration.test.ts
```

The real application rehearsal additionally depends on the Alpha.1 compiler,
Alpha.2 runtime, Alpha.3 server/claim, and Alpha.4 delivery artifacts. Alpha.8
records that integrated evidence; this guide does not claim a real application
rehearsal from the isolated Alpha.5 base.

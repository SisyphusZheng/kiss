## Contract freeze

Before broad lane implementation, freeze the smallest shared code-first contract:

- Part identity and Part kinds;
- static/dynamic Region and list representation;
- text/property/attribute/event binding semantics;
- server-visible and browser-visible program data;
- SSR marker and existing-DOM claim identity;
- compiler, runtime, SSR/claim and Island ownership boundaries.

A contract change states why the existing contract is insufficient, every affected
lane, migration impact and invalidated work. The thinker decides before implementation
continues.

## CI evidence tier

1. **Lane tier:** targeted owned tests only; no unrelated docs, security, browser,
   release or complete repository matrix.
2. **Integration tier:** cross-lane create/serialize/claim/update tests at Integration
   I, then application/Vite/Nitro tests at Integration II.
3. **Authoritative tier:** one exact-SHA full CI run when an integration checkpoint PR
   targets `dev`; absent, stale, skipped or mismatched evidence is rejected.

Integration preserves exact SHAs. Before advancing `dev`, inspect that the proposed
update is a fast-forward (`git merge --ff-only`). If fast-forward is impossible,
refresh the integration branch and require new exact-SHA PR CI rather than relabeling
old evidence. Merge commits, squash-created identities and force-pushes do not replace
the proved candidate identity.

## Integration I

Require one end-to-end vertical path:

```text
source -> compiler -> Part Program -> server HTML
                              \-> fresh browser DOM
server HTML -> existing-DOM claim -> Signal update -> subscribed Part/Region only
```

Repair interface mismatches centrally. Do not tag, publish or run release closure.

## Integration II

Require the actual framework path:

```text
authoring -> compiler -> Element -> SSR -> claim -> signals
          -> islands -> Vite -> Nitro/server -> real application
```

Only after this checkpoint may #1174 aggressively remove replaced primary paths.

## Final Alpha

performance, packed consumers and supported browser/runtime behavior. Final Alpha is
the first point that justifies comprehensive release qualification and fresh
independent verification.
